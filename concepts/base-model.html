底模是什么 ​

一句话结论： 底模（Base Model，常以 Checkpoint 文件形式出现）是 AI 绘画系统的核心生成模型，决定画面的默认风格、知识范围和能力上限；LoRA 等插件只能在这块“地基”上做加减，改变不了地基本身。

前置知识 ​

  • 已阅读 大模型入门，知道模型是训练得到的产物；LLM 部分讲过“预训练给能力，微调教用法，对齐定边界”——底模就是绘画模型的地基：它决定整体的风格倾向与能力上限。读过 训练、微调与对齐 会更顺，但不强制。
  • 不要求安装过 ComfyUI 或 WebUI，本页只建立概念，工具选择在 常用工具 展开。
  • 先接受一个边界：本页只讲底模的结构性差异（架构、分辨率、生态），不提供下载地址，也不回答“哪个模型最强”这类时效性问题。

学习目标 ​

读完后，你应该能够：

  • 说明底模在文生图系统里处于什么位置，它决定什么、不决定什么。
  • 区分底模、Checkpoint、Base Model 三个说法分别指什么。
  • 解释为什么底模决定默认画风和能力上限，以及 U-Net 与 DiT 两代架构的分野。
  • 用“地基与装修”的关系判断一个 LoRA 能不能配你的底模。
  • 拿到一个新底模时，初步判断它属于哪个生态、能配什么插件。

核心概念 ​

底模、Checkpoint、Base Model 是什么关系 ​

在不同教程里你会看到三个相近的词：

  • 底模：中文社区的习惯说法，指生成图片的核心模型。
  • Checkpoint（检查点）：底模最常见的文件形式，通常是 .safetensors 或 .ckpt。训练过程中定期保存的模型状态也叫 checkpoint，公开发布时沿用了这个名字。
  • Base Model（基座模型）：站在“训练或微调”角度的称呼。社区常说某个 LoRA 的 Base Model 是 SDXL，意思是它必须在 SDXL 这块地基上使用。

日常说“换底模”，指的就是在工具里换一个 checkpoint 文件；说“这个 LoRA 适配什么底模”，指的就是它的 Base Model 标注。三个词指向同一个东西的不同侧面。

底模在整个系统中的位置：

text
底模（生成能力的来源）
 ├─ 决定：默认画风、知识范围、分辨率习惯、生态兼容性
 └─ 不决定：构图与姿势（ControlNet 管）、附加概念（LoRA 管）、完成度（步数与采样器管）

为什么底模决定画风的“底味” ​

底模是在海量“图文对”上训练出来的。它学会的不是某一张图，而是训练数据里反复出现的统计规律：人体比例、光影习惯、线条质感、常见题材。所谓画风，就是这些规律的分布偏向：

  • 训练数据以照片为主，输出就偏写实。
  • 训练数据以插画、动漫截图为主，输出就偏二次元。
  • 提示词的写法习惯也随之定型：有的生态偏自然语言长句，有的偏标签短句。
  • 数据里某类题材过多或过少，模型就会对某些概念“偏科”。

判断一个底模的画风倾向，最快的办法不是看参数表，而是三件事：看模型页示例图的风格是否一致；读模型卡对训练数据的说明；用同一句提示词在不同底模上做对比。注意示例图是作者挑过的，别把它当成模型的平均水平。

提示词只能引导底模在已有能力范围内偏移，不能凭空创造底模没学过的能力。一个偏写实的底模很难只靠提示词稳定变成纯动画截图风格，原因就在这里——缺的不是“引导”，而是整块能力。

底模家族怎么分代：U-Net 与 DiT ​

Stable Diffusion 系列几代底模的差异，主要是结构性的：

  • SD1.5：最早普及的一代，采用 U-Net（一种以卷积为主的网络结构）做去噪，基础分辨率以 512 系为主。发布早、门槛低，围绕它积累的插件、教程和 LoRA 至今最庞大。
  • SDXL：仍沿用 U-Net 架构但规模更大，基础分辨率升到 1024 系，画面结构和细节通常更好，生态成熟度很高。
  • FLUX、Qwen-Image 等新一代：转向 DiT（Diffusion Transformer，扩散 Transformer） 类架构，普遍对自然语言长句理解更好、质感更强；工作流和 LoRA 生态与 SD 系不直接通用。

几代之间的结构关系：

text
SD1.5（U-Net，512 系分辨率）
SDXL（U-Net 加大，1024 系分辨率）
 └─ Pony / Illustrious / NoobAI 等二次元向再训练分支
FLUX / Qwen-Image 等（DiT 类架构）

同一生态内部还有变体，例如用于局部重绘的修补版、减少步数的蒸馏加速版（蒸馏：用大模型的输出训练一个更小模型的过程）。变体与主模型同属一个生态，插件兼容性通常保留，具体以发布说明为准。

架构换代的直接后果是生态不互通：LoRA、ControlNet 这类附件是针对特定底模的内部结构训练的，换一代底模就要换一套附件。所以选底模不只是选画质，也是在选一个生态。

底模与 LoRA、ControlNet 是什么关系 ​

一个常用的类比：底模是地基，插件是装修。

  • LoRA：在底模权重上叠加的小幅修改，像装修里的刷墙、换家具——能明显改变观感，但动不了承重结构，而且装修方案是针对“这一栋房”设计的，换结构就对不上。
  • ControlNet：从外部注入线稿、深度、骨架等约束，像施工图纸，管“画面长什么样”，不管“画风是什么”。
  • VAE：负责内部数据与人眼可见图片之间的转换，像门窗，属于基础设施（详见 AI 绘画由哪些部分组成）。

装修的前提是房子盖好了。底模没学过的概念，插件和提示词都很难补上。

所以搭配的顺序是：先定底模，再选装修——顺序反了，往往两头别扭。

最小推演：模型输出约等于底模底味加 LoRA 增量 ​

把“画面在写实-动漫轴上的位置”简化成一个 0 到 100 的数字（0 纯写实，100 纯动漫）。假设三个底模底味不同，同一个角色 LoRA 提供固定 +20 的增量：

底模底味（写实-动漫轴）加角色 LoRA（+20）后说明
A：偏写实1030仍偏写实，LoRA 拉不动太多
B：均衡5070偏移最明显，效果最可见
C：偏动漫80100（封顶）底味已接近上限，LoRA 无处可加，甚至过冲

推演步骤：

  1. LoRA 的影响是叠加在底模现状之上的增量，起点不同，同一个 LoRA 结果也不同。
  2. 底味已经到头的方向，LoRA 推不动，强行加大权重只会破坏画面。
  3. 所以“先选对底模、再上插件”通常比“用插件硬拗底模”可靠。
  4. 这也解释了为什么同一个 LoRA 在不同人手里效果差异很大：他们的底模底味本来就不一样。

这个推演只说明“LoRA 的效果约等于底模底味加有限增量”这一直觉，不等于真实模型里存在一个可以读出的风格数值——真实的风格空间是高维的，LoRA 修改的方向也远比“加一个数”复杂。想验证真实效果，最直接的办法是用同一句提示词、固定 seed，在有和无 LoRA 之间做对照。

对比表 ​

文生图常见的四类模型文件经常被混着问，下表按“解决什么问题”区分（各部件在流程中的位置见 AI 绘画由哪些部分组成）：

部件它是什么解决什么问题什么时候用
底模完整的生成模型（checkpoint）提供“会画什么”的全部基础能力一次生成只加载一个
LoRA底模之上的小型附加模型补充角色、画风、服装等概念挂在匹配的底模上，可叠加
VAE潜空间与像素图的编解码器把内部数据转换成人眼可见的图片底模内置或单独指定
ControlNet条件控制插件用线稿、深度、骨架约束构图与姿势构图不听话时

一句话记忆：底模管“会画什么”，LoRA 管“多画一个概念”，VAE 管“怎么变成图片”，ControlNet 管“构图听谁的”。

常见误区 ​

  • “底模越新越好”：新架构不等于适合你。生态成熟度、显存要求、LoRA 与教程数量都是现实约束，换代期旧生态往往资源更全。
  • “换个提示词就能换画风”：提示词只能在底模已有能力范围内引导。偏写实的底模很难只靠提示词稳定变成纯动漫风，反之亦然。
  • “所有 .safetensors 文件都一样”：同一扩展名下可能是 checkpoint、LoRA、VAE 或文本编码器，用途和大小量级完全不同，要按模型页说明判断。
  • “底模决定一切，参数无所谓”：采样器、步数、CFG、分辨率同样明显影响成品；底模只定上限，不出成品。
  • “名字像的底模就能混用插件”：不同大版本之间（例如 SD1.5 与 SDXL）默认不兼容，同一生态的新旧大版本也要以模型页的 Base Model 标注为准。
  • “底模就是一个文件”：新一代模型常由底模、文本编码器、VAE 等多个文件组成，缺件会导致报错或效果异常。

自测问题 ​

1. “底模”“Checkpoint”“Base Model”三个词分别强调什么？日常说“换底模”是在换什么？ ​

查看答案

底模是中文习惯说法，强调“核心生成模型”这个地位；Checkpoint 强调文件形式（通常是 .safetensors 或 .ckpt）；Base Model 站在训练角度，强调它是 LoRA 等附件所依赖的基础。日常说“换底模”，就是在工具里换一个 checkpoint 文件。

2. 为什么偏写实的底模很难只靠提示词稳定变成动漫截图风？ ​

查看答案

画风是训练数据分布的统计结果，已经写进整个模型的权重里。提示词只能在已有能力范围内引导偏移，提供不了底模没学过的完整动漫视觉规律；想稳定换风格，应该换底模，或在相近生态上用匹配的画风 LoRA 叠加。

3. 为什么 SD1.5 的 LoRA 不能默认给 SDXL 用？ ​

查看答案

LoRA 学到的是“如何修改某个底模内部权重的特定方向”，它与训练时那个底模的结构和权重分布绑定。SD1.5 与 SDXL 架构不同、权重完全不同，修改方向失去了作用对象，轻则无效，重则画面崩坏。选 LoRA 先看模型页的 Base Model 标注。
