Prompt 入门 ​

一句话：Prompt 是交给模型的任务说明和上下文，不是保证结果正确的绝对命令。不同模型、工具和工作流会用不同方式解释它。

LLM Prompt 的基本结构 ​

一个清楚的 LLM Prompt 通常包含五部分：

  • 目标：需要完成的任务。
  • 背景：完成任务所需的资料和使用场景。
  • 约束：必须遵守的规则、边界和不能做的事。
  • 输出格式：列表、表格、Markdown、JSON 或其他结构。
  • 完成标准：什么结果才算可用。

例如：

text
目标：把下面的会议记录整理成决策摘要。
背景：读者没有参加会议，需要快速了解结论。
约束：只使用原文信息；无法确认的内容标记为“待确认”。
输出格式：按“决定、负责人、截止时间、风险”四部分输出。
完成标准：每项决定都能回溯到原文。

这比只写“总结一下”更容易得到稳定、可检查的结果。

上下文、示例和边界 ​

Prompt 只应放入与任务有关的信息。材料很长时，先说明资料范围、优先级和时间版本。

当格式难以描述时，可以给一个短示例。示例应展示结构和判断方式，而不是让模型机械照抄内容。

对于高风险或最新信息，还应要求模型：

  • 区分原文事实、推断和不确定内容。
  • 给出来源或可复查位置。
  • 不知道时明确说明，不编造引用。
  • 在执行外部动作前确认权限和目标。

结构化输出与工具调用 ​

需要程序继续处理结果时，优先使用明确字段或 JSON Schema，并对返回值做解析和校验。

Function Calling 也不是模型直接执行函数。模型负责生成结构化参数，应用程序负责验证参数、调用工具、处理错误并返回结果。

如何验证 LLM 输出 ​

Prompt 调整完成后，用一组代表性样例检查：

  1. 正常输入能否得到正确结果。
  2. 缺少资料时是否会说明不确定。
  3. 输入换一种表达后，格式是否稳定。
  4. 遇到冲突材料时，是否能指出冲突。
  5. 引用、计算、代码或外部事实是否经过实际验证。

图像 Prompt ​

图像 Prompt 负责描述希望生成的视觉内容。常见信息包括：

  • 主体：人物、动物、建筑或物体。
  • 场景：室内、街道、森林或海边。
  • 风格：摄影、插画、动画截图或概念设计。
  • 光线：柔光、逆光、霓虹或自然光。
  • 构图：特写、全身、广角或俯视。

正向提示词示例：

text
a quiet street at sunset, warm light, detailed background, cinematic composition

负向提示词描述希望减少的内容：

text
low quality, blurry, watermark, text, bad anatomy, extra fingers

负向提示词不是万能修复器。它更适合减少常见问题，不能让模型凭空学会训练中没有的能力。

标签式与自然语言图像 Prompt ​

二次元模型常见标签式写法：

text
1girl, solo, school uniform, long hair, blue eyes, classroom, soft lighting

标签简洁、可组合，但需要了解模型训练时使用的标签体系。

支持自然语言的模型可以使用完整描述：

text
Create an illustration of a small robot reading a book in a cozy library, with warm lighting and a calm atmosphere.

选择哪种写法应以模型卡、官方示例和实际测试为准。

图像 Prompt 不跟手怎么办 ​

按顺序排查：

  1. 底模是否适合这个题材和提示词形式。
  2. 提示词是否互相冲突，是否需要触发词。
  3. LoRA 是否匹配底模，权重是否过高。
  4. CFG、尺寸和采样设置是否符合模型建议。
  5. 任务是否需要 ControlNet、参考图、局部重绘或后期处理。

常见误区 ​

  • 迷信固定“万能 Prompt”，忽略模型、上下文和评估标准。
  • 把所有要求都堆在一起，却没有说明优先级和冲突处理方式。
  • 要求 JSON 就认为结果一定可解析，缺少程序侧校验。
  • 复制别人的图像 Prompt 却更换了模型生态。
  • 只靠负向提示词修复结构问题，忽略模型、控制工具和后期处理。
