常见模型生态 ​

一句话结论： 模型生态不是一份排行榜，而是围绕某一代底模形成的模型文件、插件、工具、教程和许可证规则的整体；选生态先看兼容性与合规，再谈画质。

前置知识 ​

  • 已阅读 基本原理，知道去噪流水线各部件的作用。
  • 不要求已安装任何工具；本页讲“文件从哪来、怎么认、怎么读说明”，工具选择见 常用工具。
  • 先接受一个边界：本页不提供下载地址、不做时效性评测；版本名只讲结构性事实，各生态的资源情况会随时间变化。
  • 本页不涉及：具体模型的下载安装步骤与版本评测排名；动手实操见 精选教程 的官方教程入口。

学习目标 ​

读完后，你应该能够：

  • 说明模型文件主要来自哪几类渠道，以及各渠道要注意什么。
  • 凭模型页说明区分 checkpoint、LoRA、VAE、embedding、ControlNet 模型。
  • 解释 1.5 生态为什么庞大，以及新一代生态迁移的结构逻辑。
  • 读模型卡时说出必须核对的字段。
  • 按许可证规则合规地使用和发布模型产物。

核心概念 ​

模型文件从哪里来 ​

常见渠道有三类，注意点各不相同：

  • 官方发布：研究机构或公司通过官网、官方仓库、Hugging Face 等平台发布。模型卡和许可证最完整，是首选来源。
  • 社区平台：例如 Civitai，创作者发布自己训练或微调的模型、LoRA，模型页带说明、示例图和参数建议。资源丰富，但下载前仍要自己核对 Base Model 和许可证。
  • 不明来源：网盘转发、来路不明的“整合包”风险最高——文件可能被篡改，许可证也难追溯，不建议使用。

判断渠道是否可信，看三点：发布者是不是官方或实名创作者、页面说明是否完整、能否追溯到许可证。三样缺任何一样，就换渠道。

文件格式本身也值得注意：.safetensors 是为安全设计的存储格式，不夹带可执行代码；旧的 .ckpt 格式理论上能被塞入恶意代码，来源不明时优先避开。

文件类型怎么认 ​

同一个扩展名下可能是完全不同的东西，按用途区分：

  • Checkpoint（底模）：完整的生成模型，体积最大（GB 级）。
  • LoRA：挂在底模上的小型附加模型（通常几十到几百 MB 的量级），补角色、画风等概念。
  • VAE：潜空间与像素图之间的编解码器，较小，有的底模已内置。
  • Embedding（Textual Inversion，文本反转）：把一个概念压成一小段提示词向量，文件只有 KB 到几 MB。
  • ControlNet 模型：按条件类型（线稿、深度、骨架等）分类的控制模型，较大。

从文件大小反推类型并不可靠——同一后缀、相近体积的可能是不同东西。认类型以模型页说明为准，体积量级只用来做“下载得对不对”的粗检（见下面对比表）。

各类型放哪个目录、怎么加载，由工具决定，量级参考见下面对比表。

生态为什么会分代：从 1.5 到 SDXL、FLUX ​

生态分代的根源是底模换代。底模一换（架构、分辨率、文本编码器变化），旧插件就不直接通用，社区资源要重新积累：

  • SD1.5：最早普及的一代，U-Net 架构、512 系分辨率。因为门槛低、发布早，围绕它生长出的 LoRA、插件和教程至今最庞大。
  • SDXL：架构加大、分辨率升到 1024 系，生态已相当成熟。Pony、Illustrious、NoobAI 等二次元向生态多基于 SDXL 架构再训练，各有自己的标签与玩法规则（例如 Pony 系模型在训练时用 score_9 到 score_1 的质量标签给图片打分，生成时写上高分标签可提升质量，这就是常说的评分标签体系），彼此不要默认兼容。
  • FLUX、Qwen-Image、Z-Image 等新一代：DiT（Diffusion Transformer）类架构，普遍更擅长自然语言理解和质感，部分主打中文、文字渲染或图像编辑；生态仍在快速生长，教程与 LoRA 数量明显少于 SD 系。

几代之间的结构关系：

text
SD1.5（U-Net，512 系分辨率）
SDXL（U-Net 加大，1024 系分辨率）
 └─ Pony / Illustrious / NoobAI 等二次元向再训练分支
FLUX / Qwen-Image / Z-Image 等（DiT 类架构）

生态规模的差别由此而来：一代底模发布越早、门槛越低，社区在它上面攒下的 LoRA、插件和教程就越多；1.5 生态最庞大，正是因为它起步最早、活的时间最长。

同一代内部还会迭代版本（例如 v1.0、v2.0 这类编号）。版本号只代表同一生态内的更新，向后兼容性以发布说明为准，不要默认“新版本兼容旧插件”。

对初学者的含义：先固定一个生态，不要同时混用多代模型。生态迁移是社区性的长期过程，新模型未必是新手的最好起点——资源成熟度往往比“新”更重要。

按需求粗略对应：低显存或跟老教程，SD1.5；通用绘画与设计，SDXL；动漫角色与 LoRA 玩法，Pony / Illustrious / NoobAI；自然语言提示与质感体验，FLUX 等新一代。这只是一张粗略的地图，具体以你的显存和用途为准。

模型卡与许可证：用之前必须核对什么 ​

模型卡（Model Card）是模型的说明书，下载前至少核对。各平台字段名称略有差异，但以下信息几乎总能在页面上找到：

  • Base Model：它基于哪个生态，决定你的底模能不能带它。
  • 推荐参数：尺寸、步数、CFG、采样器、触发词（Trigger Words）。
  • 训练数据声明：作者用什么数据训练，涉及风格与版权边界。
  • 已知问题与更新记录：是否标注了缺陷、是否仍在维护。
  • 许可证（License）：最容易被忽略的一项。重点看三件事：能不能商用、能不能公开发布生成作品、能不能用它再训练并发布衍生模型（例如用某模型训练 LoRA 再分发）。许可证通常在模型页的 License 标签或说明区，官方模型在仓库的许可证文件里。

合规的底线：不用盗链或未授权分发的模型；公开发布作品前确认许可证允许；训练衍生模型前确认许可证允许二次创作。许可证没写清楚时，按“不允许”处理并向作者求证，而不是默认可以。

最小推演：陌生模型文件的“身份核查” ​

拿到一个陌生模型文件，先别急着加载，按顺序核对四处：

核对处看什么示例发现由此得出
1. 文件名命名是否含生态、版本、类型线索名字带“XL”字样、体积 GB 级疑似 SDXL 系 checkpoint
2. 模型卡Base Model 字段与作者说明标注 Base Model: SDXL确认是 SDXL 生态底模
3. 许可证商用、发布、二次训练条款仅允许非商用只能个人学习使用
4. 配套文件是否需要额外的 VAE、文本编码器或工作流模型卡注明需单独下载 VAE记入待办，缺件不出图

推演步骤：

  1. 文件名只做初步猜测，不能当结论——重命名太容易了。
  2. 模型卡是权威依据：确认生态、配套文件（是否需要另装 VAE 或文本编码器）和触发词。
  3. 许可证决定“能怎么用”：示例里允许下载学习、不允许商用，公开发布作品前就要另找方案。
  4. 四处任一对不上（比如名字说 XL、模型卡说 1.5），停下来向发布者求证，不硬加载。
  5. 把结论记进自己的模型清单（哪个生态、什么用途、什么限制），以后排查兼容性问题先查这份记录。

这个推演只说明“核查的顺序和依据”，不等于核查过就保证了质量与安全——来源不明的文件仍可能被篡改，尽量从官方或可信平台获取；核查记录也要随版本更新而更新。

常见误区 ​

  • “热门模型一定适合我”：热门不等于匹配——生态兼容性、显存要求、你的用途与已有插件都影响选择。
  • “一个生态就是一个模型文件”：新模型常由底模、文本编码器、VAE 等多个文件组成，缺件会导致报错或效果异常。
  • “公开发布作品不用看模型许可证”：商用、公开发布、训练衍生 LoRA 都受许可证约束，发布前要核对。
  • “.safetensors 从哪下载都一样”：来源不明的文件可能被篡改，.ckpt 还可能夹带可执行代码；认官方与可信平台。
  • “新模型一出就该立刻全面迁移”：生态（LoRA、教程、工作流）需要时间积累，迁移应按需进行，成熟度常比新旧更重要。
  • “模型、LoRA、工作流的版本可以各管各的”：它们经常按版本绑定，混搭出错时先查三者是否同代。

自测问题 ​

1. checkpoint 和 LoRA 的体积量级差多少？为什么差这么多？ ​

查看答案

checkpoint 是完整底模，通常 GB 级；LoRA 只存对底模权重的小幅修改（低秩的小矩阵），通常几十到几百 MB。因为 LoRA 冻结底模、只训练少量新增参数，所以文件小，也正因此必须挂在匹配的底模上使用；原理细节见 LoRA 入门。

2. 下载一个陌生模型前，至少要核对哪四处信息？ ​

查看答案

文件名（初步判断生态与类型）、模型卡（Base Model、推荐参数、触发词的权威依据）、许可证（能否商用、公开发布、二次训练）、配套文件（是否需要单独的 VAE 或文本编码器）。四处以模型卡和许可证为准，文件名只能当线索。

3. 想把用某模型生成的作品公开发布甚至商用，需要先看模型卡的什么字段？ ​

查看答案

看许可证条款：是否允许公开发布生成作品、是否允许商用、是否有署名等附加要求。许可证没写清楚的，默认按不允许处理，向作者求证后再用，而不是默认可以。
