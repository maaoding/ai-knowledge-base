RAG 与 Agent ​

一句话：RAG 让模型先查资料再回答，Agent 让模型根据目标规划步骤并调用工具。

RAG 是什么 ​

RAG 是 Retrieval-Augmented Generation，检索增强生成。

典型流程：

  1. 把文档切分成片段。
  2. 用 Embedding 建立语义索引。
  3. 用户提问时检索相关片段。
  4. 把片段放进上下文。
  5. 模型基于资料回答。

RAG 的核心不是“把所有文档塞给模型”，而是把最相关、可信、足够短的材料放进上下文。

RAG 适合什么 ​

适合：

  • 企业知识库问答。
  • 产品文档助手。
  • 法规、制度、手册查询。
  • 需要引用来源的总结。
  • 资料经常更新的场景。

不适合：

  • 没有可靠原始资料的问题。
  • 需要复杂事务操作但没有工具接口的问题。
  • 文档本身质量很差、互相矛盾的问题。

RAG 常见失败点 ​

  • 文档切分太碎，答案缺上下文。
  • 检索召回不准，相关资料没找到。
  • 塞入太多无关片段，模型抓不住重点。
  • 没有来源标记，无法复查。
  • 文档版本混乱，新旧规则混在一起。

Agent 是什么 ​

Agent 通常指模型不只是回答，而是围绕目标执行一组动作。

它可能会：

  • 拆解任务。
  • 选择工具。
  • 查询网页或数据库。
  • 写文件或运行代码。
  • 根据结果调整下一步。

Agent 的关键不是“像人一样自主”，而是让模型在受控边界内调用工具完成任务。

Tool Use 和 Function Calling ​

Tool Use 是模型使用外部工具的能力。Function Calling 是常见接口形式：模型输出结构化参数，由程序调用实际函数。

这样可以把模型不擅长的部分交给工具：

  • 查实时数据。
  • 运行计算。
  • 读写数据库。
  • 调用业务系统。
  • 验证文件和代码。

设计原则 ​

  • 工具权限要最小化。
  • 重要动作要有确认或审计。
  • 工具输入输出要结构化。
  • 不要让模型凭空假设工具结果。
  • 对失败路径和重试次数做限制。

RAG 和 Agent 的关系 ​

RAG 可以是 Agent 的一个工具。Agent 也可以先检索，再总结，再调用其他工具。

简单区分：

  • RAG 重点是“查资料后回答”。
  • Agent 重点是“规划和执行动作”。
  • Workflow 重点是“固定流程自动化”。
