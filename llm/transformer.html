Transformer 直觉 ​

一句话：Transformer 是现代大语言模型的核心架构，它让模型在处理 token 时能动态关注上下文里的相关部分。

为什么需要 Transformer ​

语言不是一个词一个词孤立理解的。一个词的含义取决于上下文：

  • “苹果”可能是水果，也可能是公司。
  • “它”指代谁，需要看前文。
  • 代码里的变量含义，要看定义和调用位置。

Transformer 的优势是可以并行处理序列，并通过注意力机制建立 token 之间的关系。

Attention 是什么 ​

Attention 可以理解为“当前 token 应该关注哪些上下文 token”。

例如模型看到：

text
小明把书放进书包，因为它很重。

模型需要判断“它”更可能指书还是书包。Attention 会帮助模型在上下文中给相关 token 更高权重。

Self-Attention ​

Self-Attention 是同一段输入内部互相关注。每个 token 都会根据上下文生成新的表示。

直观流程：

  1. 把 token 转成向量。
  2. 计算 token 之间的相关性。
  3. 用相关性加权汇总上下文信息。
  4. 得到更懂上下文的新向量。

这不是人工写死的规则，而是在训练中学出来的模式。

多层和多头 ​

多头注意力可以理解为从不同角度看上下文：

  • 一个头可能关注语法关系。
  • 一个头可能关注指代关系。
  • 一个头可能关注代码结构。
  • 一个头可能关注格式边界。

多层 Transformer 会逐步形成更抽象的表示。底层可能更关注局部模式，高层可能更关注任务和语义。

位置编码 ​

Attention 本身不天然知道顺序，所以模型需要位置信息。位置编码或相关机制会告诉模型 token 在序列中的位置。

这对语言很重要，因为：

  • “猫追狗”和“狗追猫”词相同但意思不同。
  • 代码、表格和列表都依赖顺序。
  • 长上下文需要识别远近关系。

常见误区 ​

  • “Attention 就是人类注意力”：只是一个数学机制，不等同于意识。
  • “Transformer 会真正理解”：它学到的是可泛化的表示和模式，不能自动保证事实正确。
  • “上下文越长越强”：长上下文还需要检索、排序和压缩，不能无限堆材料。
