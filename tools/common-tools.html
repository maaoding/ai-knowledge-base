常用工具 ​

一句话结论： 工具把模型能力包装成可用产品，但能力始终来自模型；零基础起步只需要“一个对话助手、一个绘画入口、一次本地运行尝试”，每类先用熟一个稳定的，再按真实需求扩展，不追新、不囤积。

前置知识 ​

  • 已阅读 大模型入门，知道模型与工具的分工：工具负责调用与包装，能力来自模型。
  • 读到 AI 绘画工具那半部分时，读过 底模是什么 会更顺，知道绘画工具加载的是模型文件即可。
  • 先接受一个边界：工具和功能更新很快，本页只收录多年稳定存在、官方可信的工具并描述定位，不写版本号、价格和排行榜。
  • 本页不涉及：各工具的安装排障与具体版本配置；遇到问题优先查阅工具的官方文档。

学习目标 ​

读完后，你应该能够：

  • 按用途说出五类工具各自解决什么问题、适合谁。
  • 为第一周的尝试选出一套最小工具组合，并说明理由。
  • 判断一个任务该用网页工具、本地部署还是 API。
  • 对比云端网页工具与本地部署在门槛、隐私和可控性上的差异。
  • 按“聊天框 → 预设 → API 与脚本 → 可视化工作流”的阶梯，为具体任务选工具形态。
  • 说出按量计费的成本来源，以及把数据发给公开服务前的两个检查动作。
  • 识别“囤积工具”“追新”这两类常见的时间陷阱。

核心概念 ​

对话与编程助手：先用好一个 ​

先看结构版图：对话模型分两类——闭源 API 模型（通过官方网页或 API 使用，拿不到模型文件）与开放权重模型（常被泛称为开源模型，可下载到本地跑）。中文用户常接触 Qwen、DeepSeek 等国产开放权重系列，英文生态里常见 Llama 等。粗选时看三点：对你所用语言（如中文）的能力、许可证是否允许你的用途、以及打算本地跑还是云端跑。

ChatGPT、Claude、Gemini 等网页对话助手是大多数人的第一个 AI 工具：打开网页就能问答、写作、翻译、总结和初步分析文件。GitHub Copilot 一类编程助手把同类能力嵌进代码编辑器，边写边补全和解释。

  • 适合：零基础验证想法、处理一次性任务、日常问答与写作。
  • 注意：不要上传无权处理的隐私、商业机密或受限制的数据；平台的数据使用条款和内容规则会更新，使用前看一眼当前版本。
  • 起步：先用网页版完成一个小任务，确认需求后再考虑 API 或付费方案，不必一上来就研究接口。
  • 边界：回答流畅不代表正确，重要结论仍要人工核对；模型本身的知识截止与幻觉局限并不会因为换工具而消失。

图像生成工具：网页平台与节点式工具 ​

按投入程度从低到高：

  • 网页图像平台：各模型官方或合作方提供的在线生成服务，不需要本地显卡，适合快速体验文生图、确认自己是否有长期兴趣。
  • Stable Diffusion WebUI：按钮式本地界面，适合跟随大多数传统教程、使用成熟的插件生态完成常见的图生图操作；该界面生态近年更新放缓，新项目多转向 ComfyUI。
  • ComfyUI：节点式本地界面，把生成流程拆成可自由连接的节点，适合理解模型数据流、精细控制和复用工作流（见 工作流和模板区别）。

适合想认真玩 AI 绘画、需要精细控制和可复现流程的人。本地工具的性能取决于显卡与模型生态的匹配：选底模和插件之前，先读 常见模型生态。另外，AI 出图之后通常仍需要裁剪、调色、瑕疵修复和放大，可配合 Photoshop、Krita、GIMP 等多年稳定的图像编辑工具完成；公开发布前保留来源记录并做人工筛选。

本地运行开源模型：Ollama 与同类 ​

Ollama、LM Studio、llama.cpp 可以在自己电脑上下载和运行开源模型（通常是量化后的版本；量化：用更低精度的数字存储模型参数，换取更小的显存占用），数据不出本机。

  • 适合：在意隐私、需要离线使用，或者想直观感受“模型就是一个大文件”的学习者。
  • 注意：本地效果受硬件与量化损失限制，不一定追平云端最强模型；开源不等于可以随意商用，模型许可证仍然要核对。
  • 起步：从社区验证过的小参数量模型试起，先跑通流程，再考虑更大的模型。
  • 边界：本地跑通不等于会用——模型怎么选、参数什么含义，仍要回到本站的原理页补概念。

RAG 与知识库搭建：从现成功能到框架 ​

想“针对自己的资料提问”，路径是递进的：先用对话助手自带的文件上传或现成笔记软件的 AI 功能，验证需求是否真实存在；确有定制需要时，再考虑 LangChain、LlamaIndex 这类检索增强（RAG）框架，或 Dify 这类低代码平台（原理见 RAG 与 Agent）。

如果要把模型能力接进自己的程序，则通过 API 与 SDK 调用，用于分类、信息抽取、结构化输出、问答和工具调用等固定流程。除了“能调通”，实际项目还要处理：

  • 密钥和权限管理。
  • 请求超时、限流、重试和错误记录。
  • 输入输出校验，特别是 JSON 与 Function Calling 参数。
  • 成本、延迟、模型版本和回归评估。
  • 敏感数据脱敏与审计。

框架和 API 能减少重复开发，但解决不了文档质量、切分方式和检索效果这些核心问题。API 调用成功只代表请求完成，不代表结果已经正确。

不想写代码时，另一个常见路径是 MCP 宿主：Claude、ChatGPT、VS Code、Cursor 等工具已普遍支持通过 MCP 接入外部数据与工具，原理见 RAG 与 Agent。

MCP：把“接工具”标准化成一次封装、多端复用 ​

上文的 MCP 宿主值得单独一小段，因为它正在改变“接工具”的成本结构。**MCP（Model Context Protocol，模型上下文协议，词条见术语表）**把模型应用与外部工具、数据源的对接方式标准化：一个日历、笔记库或数据库按协议把自己的能力封装一次，支持 MCP 的宿主应用就都能发现并调用它，不必在每个应用里单独适配一遍。

对不写代码的普通用户，这意味着两件事。一是给助手接上外部能力的门槛在降低：很多常用服务的 MCP 接入已经做到“填一份配置”的程度。二是权限的分量随之上升：能读你笔记库的助手和只会聊天的助手是两种风险等级，接入前看清它申请了什么权限、能触达哪些数据，高危动作（发送、删除、花钱）保留人工确认。协议原理与安全展开见 RAG 与 Agent。

学习平台：模型卡与官方课程 ​

  • Hugging Face：开源模型与数据集的主要集散地；读模型卡（Model Card）是使用任何模型前的第一步。
  • Google 机器学习课程：官方出品的系统课程，适合在动手前补齐概念。
  • Hugging Face LLM Course：掌握基础概念后，继续深入原理与实践。

工具的界面年年变，平台和课程稳定得多。完整清单见 常用网站，进阶教程见 精选教程。

选型阶梯：从聊天框到可视化工作流 ​

按投入从低到高，五类工具可以理成一条四级阶梯，每一级都有“该往上走”的典型信号：

  • 聊天框（网页对话助手）：一次性任务、低频使用、每次内容都不同，直接问就好。升级信号：同样一段任务说明每周都要重新手打一遍。
  • 带预设的工具（自定义指令、项目知识、绘画平台的参数预设）：把重复使用的六要素沉淀成固定起点，每次只填变化的部分。升级信号：任务开始需要固定的多个步骤，或要把结果交给程序继续处理。
  • API 加脚本：把模型调用写进自己的流程，稳定输出格式、批量处理、接入自有数据。升级信号：步骤之间出现依赖和分支，顺序执行的脚本难以表达。
  • 可视化工作流（ComfyUI、低代码平台）：把检索、模型调用、条件分支连成节点图，适合精细控制与复用流程。

四级不是所有人都要走满：多数人的长期停留点在第二级，够用就停。这条阶梯与工作流和模板区别的“一条 Prompt → 模板 → 半自动 → 工作流”是同一件事的两个视角——那页讲升级的四条判断标准，本页给每一级对应的具体工具形态与典型信号。犹豫时先回那页的升级四标准（依赖、分支、工具、频率）做判断，再回这张表对号入座。

成本与隐私：选型前先过的两道账 ​

成本：Token 按量计价的原理见大模型入门，这里只说选工具时怎么算账。订阅制是固定成本，适合日常对话；API 与自动化流程是浮动成本，随用量线性增长，大头来自三处——长上下文（整份文档反复粘贴）、长输出（要求写长文）、高频调用（自动化流程定时反复跑）。上线任何自动化之前先做一道乘法：单次调用的 Token 费用乘以调用频率，再乘以一个月，很多“顺手自动化”的成本就是被这道乘法照出来的。用 API 时给账户设用量上限和告警，是比事后看账单有效得多的止损手段。

隐私：把数据交给公开服务前，至少确认两件事。一是数据去向：平台的条款是否允许留存对话、是否用于改进服务。二是脱敏：贴进对话框之前，把姓名、工号、密钥、客户信息这类可识别内容去掉或替换，只保留任务需要的结构——脱敏的成本远低于泄漏的代价。要求更高时，前面对比表里的本地部署是兜底选项：数据不出本机，代价是硬件与维护。

工具会过时，能力可迁移 ​

本页列出的具体产品，几年后未必都还在；真正保值的，是下面三条可迁移的能力：

  • 把任务写清楚：六要素的写法不绑定任何工具，换一个助手照样适用（见 Prompt 入门）。
  • 用固定考卷判断效果：改动有没有用、新模型值不值得换，评估方法走到哪个工具里都一样（见 效果评估）。
  • 把多步骤组织成可控的流程：检查点、条件分支、错误处理的设计思想，从聊天框到工作流平台通用（见 工作流和模板区别）。

所以换新工具时，正确姿势不是从零焦虑，而是把这三件事在新工具里重新落地：写一条六要素齐备的任务说明，跑一遍自己的小考卷，需要时再搭流程。工具是这些能力的容器——容器会换，能力跟着人走。

动手试试：第一个工具组合 ​

第一周不建议同时开五六个工具。一套覆盖三条理解路径的最小组合：

用途起点建议一句理由
对话任一主流网页对话助手零门槛，当天就能验证本站讲的 Token、幻觉这些概念
绘画一个网页图像平台不依赖本地显卡，先确认兴趣，再决定要不要装 ComfyUI
本地尝试用 Ollama 跑一个开源小模型一条命令体验“模型在自己电脑上”，建立模型即文件的直觉

第一周的行动顺序：

  1. 用对话助手照着 Prompt 入门 的六要素写几条任务说明，感受结构化写法与随手一问的差别。
  2. 在绘画平台用同一句提示词只换风格词，观察模型如何响应。
  3. 用 Ollama 跑通一个小模型，问它一件训练截止之后发生的事，亲眼看到知识截止。
  4. 把三条路径的体会各记一句话——记录比工具本身更保值。

工具用起来之后，建议记录：模型名称、来源和许可证；模型卡里的推荐参数；自己验证过的 Prompt 与参数组合；遇到过的失败模式。以后排查问题时，先查这份清单。

搭配原则：每类先用熟一个，遇到真实瓶颈（隐私、离线、精细控制、规模化）再引入第二个工具。组合没有唯一正解，稳定和够用比多更重要。

对比表 ​

云端与本地不是二选一，而是同一张地图上的两端：

维度云端网页工具本地部署
上手门槛注册即用，无硬件要求需要安装配置和一定硬件
成本形态订阅或按量付费硬件与电费为主，模型多为开源
隐私数据交给服务商，取决于平台条款数据不出本机
可控性模型版本与功能由平台决定模型、参数、更新节奏自己控制
能力上限通常能用上最强模型受本地硬件与量化损失限制
维护负担平台负责更新与运维升级、排错、环境管理都靠自己
适用人群零基础体验与日常使用重隐私、需离线、想弄懂原理的学习者

费用形态上，云端工具多为订阅制或按用量计费，本地部署主要成本是一次性硬件与电费；API 类服务通常把输入与输出分开按 Token 计价，长上下文会显著放大费用。

很多人的实际路径是：日常用云端，涉及敏感资料或想学原理时转本地。选哪端，先看任务对隐私和可控性的要求，再看自己的硬件和时间预算。

按任务快速对号入座：

  • 一次性体验、随手一问：网页对话助手或网页图像平台。
  • 固定的应用流程（分类、抽取、结构化输出）：API，并建立日志、校验和评估。
  • 隐私或离线要求：本地运行开源模型，先评估硬件成本。
  • 经常查询自有资料：先做简单 RAG 验证需求，再考虑 Agent 框架。
  • 需要精细图像控制：Stable Diffusion WebUI 或 ComfyUI，并保留可复现的工作流。

常见误区 ​

  • “工具越多越好”：工具只负责调用，能力来自模型；概念没搞清之前囤积工具，只会在界面之间迷路。
  • “新工具一出就该换掉旧的”：新工具迭代快、寿命不定；优先用多年稳定存在的，等新工具有了清晰定位再试不迟。
  • “本地模型一定更安全、更好”：本地解决的是数据不出本机的问题，不改变模型本身的能力上限，也不豁免许可证约束。
  • “API 调用成功就等于结果正确”：请求完成只代表链路通了，内容仍要做校验和评估。
  • “RAG 框架装好就有知识库”：文档切分、检索质量和来源管理才是难点，框架只是脚手架。
  • “平台功能等于模型能力”：联网搜索、文件分析是工具层的功能，模型本身的知识截止和局限并没有变。
  • “订阅制就等于成本封顶”：订阅只覆盖对话入口，API 调用与自动化流程按量计费的部分会随规模增长；上线自动化前先算单次成本乘频率。
  • “换新工具就要从零学起”：界面操作会过时，写清楚任务、评估效果、组织流程的能力可迁移；换工具是把已有方法在新容器里重新落地，不是推倒重来。

自测问题 ​

1. 第一周只配“一个对话助手 + 一个网页绘画平台 + 一次本地运行”，为什么这么配？ ​

查看答案

三类工具覆盖三条最低成本的理解路径：对话助手验证语言模型的能力与局限，网页绘画确认自己是否有兴趣，本地运行建立“模型是文件、可以自己跑”的直觉。每类只选一个，是为了把时间花在概念上而不是工具切换上。

2. 要求“内部资料不能上传到任何云端”，应该选哪类工具？要注意什么？ ​

查看答案

选本地运行开源模型的工具（如 Ollama、LM Studio），数据不出本机。要注意：本地硬件是否带得动目标模型、模型许可证是否允许你的用途，以及本地小模型的效果通常低于云端最强模型，复杂任务要先做评估。

3. “新出的工具要不要马上换掉现在用的？”怎么判断？ ​

查看答案

默认不换。判断标准：新工具是否已稳定存在一段时间、是否解决了你现在的真实瓶颈、迁移成本多大。如果现在的工具够用，追新消耗的是学习概念和积累经验的时间；真有瓶颈时，也先在旧工具里确认问题无法解决再迁移。

4. 你每周要把同一段任务说明手动粘贴进聊天框十几次，现在该升级到哪一级？出现什么信号才值得继续往上走？ ​

查看答案

先升到带预设的工具：把这段任务说明沉淀进自定义指令或项目知识，每次只填变化的部分。继续往上走的信号是任务开始需要固定的多步骤、条件分支，或要把结果交给程序处理——那时再考虑 API 加脚本或可视化工作流。是否值得继续走，判断标准与工作流页的升级四标准一致。

5. 打算把一个内部流程做成每小时自动调用几次模型的定时任务，上线前除了效果评估，还要过哪两道账？ ​

查看答案

成本账：单次调用的 Token 费用乘以每小时调用次数，再乘以预计运行时长——长上下文会显著放大这笔钱；同时给账户设用量上限与告警，防止流程出错时反复调用烧穿预算。隐私账：确认喂给模型的输入里有没有姓名、编号、密钥这类可识别内容，有则先脱敏，或改用本地部署让数据不出本机。
