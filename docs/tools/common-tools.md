# 常用工具

> **一句话结论：** 工具把模型能力包装成可用产品，但能力始终来自模型；零基础起步只需要“一个对话助手、一个绘画入口、一次本地运行尝试”，每类先用熟一个稳定的，再按真实需求扩展，不追新、不囤积。

本页链接与描述核对于 2026 年 9 月；工具与平台迭代较快，使用前请以官方页面为准。

## 前置知识

- 已阅读 [大模型入门](/llm/basics)，知道模型与工具的分工：工具负责调用与包装，能力来自模型。
- 已阅读 [底模是什么](/concepts/base-model)，知道 AI 绘画工具加载的是模型文件。
- 先接受一个边界：工具和功能更新很快，本页只收录多年稳定存在、官方可信的工具并描述定位，不写版本号、价格和排行榜。
- **本页不涉及**：各工具的安装排障与具体版本配置；遇到问题优先查阅工具的官方文档。

## 学习目标

读完后，你应该能够：

- 按用途说出五类工具各自解决什么问题、适合谁。
- 为第一周的尝试选出一套最小工具组合，并说明理由。
- 判断一个任务该用网页工具、本地部署还是 API。
- 对比云端网页工具与本地部署在门槛、隐私和可控性上的差异。
- 识别“囤积工具”“追新”这两类常见的时间陷阱。

## 核心概念

### 对话与编程助手：先用好一个

先看结构版图：对话模型分两类——闭源 API 模型（通过官方网页或 API 使用，拿不到模型文件）与开放权重模型（常被泛称为开源模型，可下载到本地跑）。中文用户常接触 Qwen、DeepSeek 等国产开放权重系列，英文生态里常见 Llama 等。粗选时看三点：对你所用语言（如中文）的能力、许可证是否允许你的用途、以及打算本地跑还是云端跑。

ChatGPT、Claude、Gemini 等网页对话助手是大多数人的第一个 AI 工具：打开网页就能问答、写作、翻译、总结和初步分析文件。GitHub Copilot 一类编程助手把同类能力嵌进代码编辑器，边写边补全和解释。

- 适合：零基础验证想法、处理一次性任务、日常问答与写作。
- 注意：不要上传无权处理的隐私、商业机密或受限制的数据；平台的数据使用条款和内容规则会更新，使用前看一眼当前版本。
- 起步：先用网页版完成一个小任务，确认需求后再考虑 API 或付费方案，不必一上来就研究接口。
- 边界：回答流畅不代表正确，重要结论仍要人工核对；模型本身的知识截止与幻觉局限并不会因为换工具而消失。

### 图像生成工具：网页平台与节点式工具

按投入程度从低到高：

- **网页图像平台**：各模型官方或合作方提供的在线生成服务，不需要本地显卡，适合快速体验文生图、确认自己是否有长期兴趣。
- **Stable Diffusion WebUI**：按钮式本地界面，适合跟随大多数传统教程、使用成熟的插件生态完成常见的图生图操作。
- **ComfyUI**：节点式本地界面，把生成流程拆成可自由连接的节点，适合理解模型数据流、精细控制和复用工作流（见 [工作流和模板区别](/workflows/workflow-vs-template)）。

适合想认真玩 AI 绘画、需要精细控制和可复现流程的人。本地工具的性能取决于显卡与模型生态的匹配：选底模和插件之前，先读 [常见模型生态](/models/ecosystems)。另外，AI 出图之后通常仍需要裁剪、调色、瑕疵修复和放大，可配合 Photoshop、Krita、GIMP 等多年稳定的图像编辑工具完成；公开发布前保留来源记录并做人工筛选。

### 本地运行开源模型：Ollama 与同类

Ollama、LM Studio、llama.cpp 可以在自己电脑上下载和运行开源模型（通常是量化后的版本；量化：用更低精度的数字存储模型参数，换取更小显存占用），数据不出本机。

- 适合：在意隐私、需要离线使用，或者想直观感受“模型就是一个大文件”的学习者。
- 注意：本地效果受硬件与量化损失限制，不一定追平云端最强模型；开源不等于可以随意商用，模型许可证仍然要核对。
- 起步：从社区验证过的小参数量模型试起，先跑通流程，再考虑更大的模型。
- 边界：本地跑通不等于会用——模型怎么选、参数什么含义，仍要回到本站的原理页补概念。

### RAG 与知识库搭建：从现成功能到框架

想“针对自己的资料提问”，路径是递进的：先用对话助手自带的文件上传或现成笔记软件的 AI 功能，验证需求是否真实存在；确有定制需要时，再考虑 LangChain、LlamaIndex 这类检索增强（RAG）框架，或 Dify 这类低代码平台（原理见 [RAG 与 Agent](/llm/rag-agent)）。

如果要把模型能力接进自己的程序，则通过 API 与 SDK 调用，用于分类、信息抽取、结构化输出、问答和工具调用等固定流程。除了“能调通”，实际项目还要处理：

- 密钥和权限管理。
- 请求超时、限流、重试和错误记录。
- 输入输出校验，特别是 JSON 与 Function Calling 参数。
- 成本、延迟、模型版本和回归评估。
- 敏感数据脱敏与审计。

框架和 API 能减少重复开发，但解决不了文档质量、切分方式和检索效果这些核心问题。API 调用成功只代表请求完成，不代表结果已经正确。

### 学习平台：模型卡与官方课程

- **Hugging Face**：开源模型与数据集的主要集散地；读模型卡（Model Card）是使用任何模型前的第一步。
- **Google 机器学习课程**：官方出品的系统课程，负责在动手前补齐概念。
- **Hugging Face LLM Course**：掌握基础概念后，继续深入原理与实践。

工具的界面年年变，平台和课程稳定得多。完整清单见 [常用网站](/resources/websites)，进阶教程见 [精选教程](/resources/tutorials)。

## 动手试试：第一个工具组合

第一周不建议同时开五六个工具。一套覆盖三条理解路径的最小组合：

| 用途 | 起点建议 | 一句理由 |
| --- | --- | --- |
| 对话 | 任一主流网页对话助手 | 零门槛，当天就能验证本站讲的 Token、幻觉这些概念 |
| 绘画 | 一个网页图像平台 | 不依赖本地显卡，先确认兴趣，再决定要不要装 ComfyUI |
| 本地尝试 | 用 Ollama 跑一个开源小模型 | 一条命令体验“模型在自己电脑上”，建立模型即文件的直觉 |

第一周的行动顺序：

1. 用对话助手照着 [Prompt 入门](/prompting/basics) 的六要素写几条任务说明，感受结构化写法与随手一问的差别。
2. 在绘画平台用同一句提示词只换风格词，观察模型如何响应。
3. 用 Ollama 跑通一个小模型，问它一件训练截止之后发生的事，亲眼看到知识截止。
4. 把三条路径的体会各记一句话——记录比工具本身更保值。

随着工具用起来，建议记录：模型名称、来源和许可证；模型卡里的推荐参数；自己验证过的 Prompt 与参数组合；遇到过的失败模式。以后排查问题时，先查这份清单。

搭配原则：每类先用熟一个，遇到真实瓶颈（隐私、离线、精细控制、规模化）再引入第二个工具。组合没有唯一正解，稳定和够用比多更重要。

## 对比表

云端与本地不是二选一，而是同一张地图上的两端：

| 维度 | 云端网页工具 | 本地部署 |
| --- | --- | --- |
| 上手门槛 | 注册即用，无硬件要求 | 需要安装配置和一定硬件 |
| 成本形态 | 订阅或按量付费 | 硬件与电费为主，模型多为开源 |
| 隐私 | 数据交给服务商，取决于平台条款 | 数据不出本机 |
| 可控性 | 模型版本与功能由平台决定 | 模型、参数、更新节奏自己控制 |
| 能力上限 | 通常能用上最强模型 | 受本地硬件与量化损失限制 |
| 维护负担 | 平台负责更新与运维 | 升级、排错、环境管理都靠自己 |
| 适用人群 | 零基础体验与日常使用 | 重隐私、需离线、想弄懂原理的学习者 |

费用形态上，云端工具多为订阅制或按用量计费，本地部署主要成本是一次性硬件与电费；API 类服务通常把输入与输出分开按 Token 计价，长上下文会显著放大费用。

很多人的实际路径是：日常用云端，涉及敏感资料或想学原理时转本地。选哪端，先看任务对隐私和可控性的要求，再看自己的硬件和时间预算。

按任务快速对号入座：

- 一次性体验、随手一问：网页对话助手或网页图像平台。
- 固定的应用流程（分类、抽取、结构化输出）：API，并建立日志、校验和评估。
- 隐私或离线要求：本地运行开源模型，先评估硬件成本。
- 经常查询自有资料：先做简单 RAG 验证需求，再考虑 Agent 框架。
- 需要精细图像控制：Stable Diffusion WebUI 或 ComfyUI，并保留可复现的工作流。

## 常见误区

- **“工具越多越好”**：工具只负责调用，能力来自模型；概念没搞清之前囤积工具，只会在界面之间迷路。
- **“新工具一出就该换掉旧的”**：新工具迭代快、寿命不定；优先用多年稳定存在的，等新工具有了清晰定位再试不迟。
- **“本地模型一定更安全、更好”**：本地解决的是数据不出本机的问题，不改变模型本身的能力上限，也不豁免许可证约束。
- **“API 调用成功就等于结果正确”**：请求完成只代表链路通了，内容仍要做校验和评估。
- **“RAG 框架装好就有知识库”**：文档切分、检索质量和来源管理才是难点，框架只是脚手架。
- **“平台功能等于模型能力”**：联网搜索、文件分析是工具层的功能，模型本身的知识截止和局限并没有变。

## 自测问题

### 1. 第一周只配“一个对话助手 + 一个网页绘画平台 + 一次本地运行”，为什么这么配？

<details>
<summary>查看答案</summary>

三类工具覆盖三条最低成本的理解路径：对话助手验证语言模型的能力与局限，网页绘画确认自己是否有兴趣，本地运行建立“模型是文件、可以自己跑”的直觉。每类只选一个，是为了把时间花在概念上而不是工具切换上。

</details>

### 2. 要求“内部资料不能上传到任何云端”，应该选哪类工具？要注意什么？

<details>
<summary>查看答案</summary>

选本地运行开源模型的工具（如 Ollama、LM Studio），数据不出本机。要注意：本地硬件是否带得动目标模型、模型许可证是否允许你的用途，以及本地小模型的效果通常低于云端最强模型，复杂任务要先做评估。

</details>

### 3. “新出的工具要不要马上换掉现在用的？”怎么判断？

<details>
<summary>查看答案</summary>

默认不换。判断标准：新工具是否已稳定存在一段时间、是否解决了你现在的真实瓶颈、迁移成本多大。如果现在的工具够用，追新消耗的是学习概念和积累经验的时间；真有瓶颈时，也先在旧工具里确认问题无法解决再迁移。

</details>
