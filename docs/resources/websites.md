# 常用网站

> **一句话结论：** 这份清单按用途分组：先用官方课程补概念，再用平台查模型与论文，最后按工具找官方文档；每个条目附“选用”提示，说明什么时候用、什么时候跳过。下载或引用任何资源前，先核对发布者、模型卡（Model Card）和许可证（License）——外部资源随时可能更新，遇到冲突以官方为准。

本页链接与描述核对于 2026 年 9 月；网站与平台迭代较快，使用前请以官方页面为准。

## 学习目标

读完后，你应该能够：

- 按用途从本页七组资源里选出当下需要的一两个，而不是全部收藏。
- 说出核对一个外部资源的六个检查点：官方性、更新时间、许可证、发布者、社区热度、交叉验证。
- 在下载一个模型前，按“发布者 → 模型卡 → 许可证 → 文件与量化 → 社区反馈 → 记录存档”的顺序做一遍尽调。
- 解释为什么预印本、Star 数、跑通教程都不能单独作为可信依据。
- 用“来源、版本、访问日期、关键配置”四项记录，保证以后能复查。

## 模型与数据平台

这组解决“模型从哪来、怎么读说明”：下载前在这里核对模型卡、许可证和推荐参数。

### Hugging Face

地址：[https://huggingface.co](https://huggingface.co)

用途：

- 查找模型、数据集、演示和官方文档。
- 查看模型卡、许可证、文件结构和推荐用法。
- 比较不同任务、框架和模型版本。

下载或调用模型前先核对发布者、许可证、所需文件、量化（Quantization）格式和用途限制。

选用：找模型、读模型卡的第一站；不该用它做的事是照搬别人的“整合包”——下载前仍要回到原始发布页核对。

### Civitai

地址：[https://civitai.com](https://civitai.com)

用途：

- 查找 AI 绘画 checkpoint、LoRA、VAE、工作流和示例图。
- 查看示例 Prompt、推荐参数和社区反馈。

这是社区平台，模型质量、来源、许可证和内容分级差异很大，公开使用前要逐项核对。

选用：找绘画底模、LoRA 和工作流参考时用；作品要公开发布或商用时，不能只依赖这里的社区标签，许可证要回原始发布页逐项确认。

选用：每天花几分钟跟踪新方向时用；不适合系统学习，也不要把热门排序当成质量保证。

## 怎么判断一个资源靠不靠谱

本页收录的条目都按下面的标准筛过；更重要的是，你以后遇到本页之外的网站、模型和教程，也可以用同样的六道检查。

1. **官方优先，并确认“官方”是真的。** 官方文档、模型卡和官方示例通常更接近一手信息，但也会过期或存在版本差异。冒名页面和“官网风格”的聚合站不少：确认方法是看域名是否属于发布机构（例如 Google 的课程在 developers.google.com 下）、模型页发布者是否是该机构的官方账号、链接能否从官方 GitHub 仓库或论文主页跳转到达。搜索引擎排第一、被浏览器插件推荐，都不算确认。
2. **看更新时间。** 文档的“最后更新”日期、仓库的最近提交、课程的版本号，说明内容还活着。AI 领域以月为单位迭代，两年没动的教程即使当时正确，涉及的 API 和模型也多半已经变了。
3. **看许可证与用途限制。** 开源不等于可以随意商用：LICENSE 文件和模型卡写明能不能商用、要不要署名、有没有附加条款；数据集和绘画素材还可能限制转售或公开分发。微调、量化都不改变原始许可证的约束。拿不准就先当不能用。
4. **确认发布者身份。** 同一个模型名下，可能有官方原版、官方微调、第三方重打包和来路不明的改名版。优先用发布机构自己账号下的页面；第三方上传的版本，要能说清改了什么、是否获得授权。
5. **警惕社区热度的局限。** Star 数、点赞和“全网都在转”衡量的是注意力，不是正确性：热度可以靠营销堆起来，热门论文被复现失败也不罕见。热度可以当线索，不能当结论。
6. **多方交叉验证。** 重要结论至少找两个独立来源：论文看原文而不是转述，参数回到官方文档，教程里的命令和官方 README 对一遍。注意，两个来源互相引用不算独立——很多转述内容追根溯源是同一篇预印本。

## 最小推演：给一次模型下载做尽调

下面走一遍完整流程。场景是虚构的：你想给本地写作工具找一个中文小说续写模型，在模型平台搜到 “story-teller-8b”，发布者署名 “story-fan-2026”，下载按钮就在眼前。先别点，按六步走。

第 1 步，查发布者。点开发布者主页：个人账号，没有组织认证，名下只有这一个模型。回到搜索，发现组织账号 “story-lab” 下有同名模型，模型卡写明这是官方微调版。——改用组织账号的版本，个人重打包版直接排除。

第 2 步，读模型卡。组织版的模型卡写清：基于哪个基座模型（Base Model）、用了什么训练数据、推荐参数、已知局限。基座怎么决定微调版的能力与授权边界，见 [底模是什么](/concepts/base-model)。反面信号是模型卡只有一句“效果很好”——连作者都说不清它是什么。

第 3 步，核对许可证。基座模型的许可证是“仅限非商用”，微调版通常不能因为微调就自动获得更宽的授权；但“非商用”也不能概括所有个人使用、再分发、生成内容、依赖组件和平台条款。用途或条款不清时，不要默认可以使用；如果打算接进收费服务，应换成明确允许该用途的模型或先取得授权。

第 4 步，看文件与量化。文件列表里有 FP16 原始权重（约 16 GB）和一份 Q4 量化版（约 5 GB；量化指用更低精度的数字存储模型参数，换取更小体积）。显卡只有 8 GB 显存时，Q4 只能作为候选：还要为运行时框架、KV Cache、上下文和系统共享显存预留余量，必要时降低上下文或批量，甚至选择更小的模型。文件体积不等于实际显存占用；同时核对文件名里的量化等级与说明一致，防止下到被改名重打包的版本。

第 5 步，翻社区反馈。讨论区有人报告“长对话后开始重复输出”，作者回复并更新了推荐参数；没有恶意行为的报告。——有具体问题的讨论比清一色叫好更有信息量；反馈当参考，不当担保。

第 6 步，记录存档。下载完成，当场记一行：模型名、发布页地址、版本号（commit）、许可证、量化等级、下载日期、推荐参数。三个月后出问题，先查这行记录。

哪一步偷懒，代价是什么：

| 偷懒的步骤 | 可能的后果 |
| --- | --- |
| 跳过发布者核对 | 装上来路不明的重打包版，轻则效果不对，重则夹带恶意内容 |
| 跳过模型卡 | 高估了模型能力，下载之后发现根本不适合你的任务 |
| 跳过许可证核对 | 服务上线后收到权利方函件，只能下线重做 |
| 跳过文件核对 | 下了 16 GB 原始权重，可能因显存或内存装不下，白等半小时下载 |
| 跳过社区反馈 | 社区早已报告的问题，你再踩一遍 |
| 跳过记录存档 | “这个模型当时从哪下的”没人记得，复现与排错无从谈起 |

## 使用外部资源的原则

上一节是“用之前怎么筛”，这一节是筛过之后的使用习惯：

- 判断不过关的资源不用；不因为“大家都在用”而放行。
- 不把未知来源的模型、数据、角色或素材直接用于公开或商业项目；先核实授权，再谈使用。
- 社区教程用来补充操作经验；涉及参数、下载和兼容性时，回到官方资料核对当前版本。
- 记录来源、版本、访问日期和关键配置；外部资源会更新或消失，你的记录才是稳定的复查依据。
- 转述或引用时注明出处和访问日期，让读的人也能复查。

## 常见误区

- **“预印本等于定论”**：预印本未经同行评审，结论可能被后续研究修正甚至推翻；引用前看有没有正式发表版本和复现结果。
- **“Star 多等于可靠”**：Star 衡量关注度，不衡量正确性；刷量、营销和“方便收藏”都会推高数字，安全漏洞和复现失败也常发生在热门项目上。
- **“教程能跑通就等于理解了”**：照抄命令只能得到一次成功，换个版本、换个模型就报错；能说清每一步在做什么、失败后从哪查起，才算理解。
- **“收藏了链接等于有了资料”**：链接会失效、页面会改版；真正可复用的是你自己的记录——来源、版本、关键参数，以及当时为什么选它。
- **“官网内容永远有效”**：官网也会过期——产品下线、API 改版、公告撤回都会发生；看官网要顺带看发布日期，遇到冲突以当前官方页面为准。
- **“聚合站比官方文档好读，就以它为准”**：聚合站内容经过转述，滞后和失真都常见；可以当入门线索，但参数和结论要回到官方来源核对。

## 自测问题

### 1. 同一个模型名能搜到个人账号和组织账号两个版本，选哪个？为什么？

<details>
<summary>查看答案</summary>

优先选组织（官方）账号下的版本：发布者身份可以确认，模型卡、许可证和更新记录通常更完整。个人重打包版可能改动不明、授权不清；除非它明确说明改了什么且确有需要，否则不作为第一选择。

</details>

### 2. 找到一篇讲新技术原理的文章，写得清楚易懂，怎么决定能不能直接引用它的结论？

<details>
<summary>查看答案</summary>

把它当线索，不当来源：顺着它找到原始论文或官方文档，核对结论是否一致、信息是否更新；涉及关键数字和参数时，以原始来源为准。多个二手来源互相引用不算独立验证——它们可能都出自同一篇预印本。

</details>

### 3. 三个月前下载过一个微调模型，现在生成的结果和当时不一样，第一步做什么？

<details>
<summary>查看答案</summary>

先查当时记录下的来源、版本号和推荐参数——这正是下载后当场存档的意义。确认是模型版本变了、参数不同，还是运行工具更新所致，再回到发布页核对该版本的模型卡和更新说明。

</details>
