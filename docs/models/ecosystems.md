# 常见模型生态

> **一句话结论：** 模型生态不是一份排行榜，而是围绕某一代底模形成的模型文件、插件、工具、教程和许可证规则的整体；选生态先看兼容性与合规，再谈画质。

## 前置知识

- 已阅读 [基本原理](/concepts/how-it-works)，知道去噪流水线各部件的作用。
- 不要求已安装任何工具；本页讲“文件从哪来、怎么认、怎么读说明”，工具选择见 [常用工具](/tools/common-tools)。
- 先接受一个边界：本页不提供下载地址、不做时效性评测；版本名只讲结构性事实，各生态的资源情况会随时间变化。
- **本页不涉及**：具体模型的下载安装步骤与版本评测排名；动手实操见 [精选教程](/resources/tutorials) 的官方教程入口。

## 学习目标

读完后，你应该能够：

- 说明模型文件主要来自哪几类渠道，以及各渠道要注意什么。
- 凭模型页说明区分 checkpoint、LoRA、VAE、embedding、ControlNet 模型。
- 解释 1.5 生态为什么庞大，以及新一代生态迁移的结构逻辑。
- 读模型卡时说出必须核对的字段。
- 按许可证规则合规地使用和发布模型产物。
- 拆读模型文件名，分清家族、代际、变体与作者版本号。
- 用三件事判断一个生态的厚度，并据此评估上手成本。

## 核心概念

### 模型文件从哪里来

常见渠道有三类，注意点各不相同：

- **官方发布**：研究机构或公司通过官网、官方仓库、Hugging Face 等平台发布。模型卡和许可证最完整，是首选来源。
- **社区平台**：例如 Civitai，创作者发布自己训练或微调的模型、LoRA，模型页带说明、示例图和参数建议。资源丰富，但下载前仍要自己核对 Base Model 和许可证。
- **不明来源**：网盘转发、来路不明的“整合包”风险最高——文件可能被篡改，许可证也难追溯，不建议使用。

判断渠道是否可信，看三点：发布者是不是官方或实名创作者、页面说明是否完整、能否追溯到许可证。三样缺任何一样，就换渠道。

文件格式本身也值得注意：`.safetensors` 是为安全设计的存储格式，不夹带可执行代码；旧的 `.ckpt` 格式可能被塞入可执行代码，来源不明时优先避开。

### 文件类型怎么认

同一个扩展名下可能是完全不同的东西，按用途区分：

- **Checkpoint（底模）**：完整的生成模型，体积最大（GB 级）。
- **LoRA**：挂在底模上的小型附加模型（通常几十到几百 MB 的量级），补角色、画风等概念。
- **VAE**：潜空间与像素图之间的编解码器，较小，有的底模已内置。
- **Embedding（Textual Inversion，文本反转）**：把一个概念压成一小段提示词向量，文件只有 KB 到几 MB。
- **ControlNet 模型**：按条件类型（线稿、深度、骨架等）分类的控制模型，较大。

从文件大小反推类型并不可靠——同一后缀、相近体积的可能是不同东西。认类型以模型页说明为准，体积量级只用来做“下载得对不对”的粗检（见下面对比表）。

各类型放哪个目录、怎么加载，由工具决定，量级参考见下面对比表。

### 生态为什么会分代：从 1.5 到 SDXL、FLUX

生态分代的根源是底模换代：底模一换（架构、分辨率、文本编码器变化），旧插件就不直接通用，社区资源要重新积累。各代底模的结构差异与谱系图见[底模是什么](/concepts/base-model)，本页只看生态角度：SD1.5 生态起步最早、门槛最低，围绕它的 LoRA、插件和教程至今最庞大；SDXL 生态已相当成熟，Pony、Illustrious、NoobAI 等二次元向生态多基于 SDXL 架构再训练，各有自己的标签与玩法规则（例如 Pony 系模型在训练时用 score_9 到 score_1 的质量标签给图片打分，生成时写上高分标签可提升质量，这就是常说的评分标签体系），彼此不要默认兼容；SD3 / SD3.5 与 FLUX（含 2025 年 11 月发布的 FLUX.2）、Qwen-Image、Z-Image 等新一代转向 DiT 类架构，生态仍在快速生长，教程与 LoRA 数量明显少于 SD 系。

生态规模的差别由此而来：一代底模发布越早、门槛越低，社区在它上面攒下的 LoRA、插件和教程就越多；1.5 生态最庞大，正是因为它起步最早、活的时间最长。

同一代内部还会迭代版本（例如 v1.0、v2.0 这类编号）。版本号只代表同一生态内的更新，向后兼容性以发布说明为准，不要默认“新版本兼容旧插件”。

对初学者的含义：**先固定一个生态**，不要同时混用多代模型。生态迁移是社区性的长期过程，新模型未必是新手的最好起点——资源成熟度往往比“新”更重要。

按需求粗略对应：低显存或跟老教程，SD1.5；通用绘画与设计，SDXL；动漫角色与 LoRA 玩法，Pony / Illustrious / NoobAI；自然语言提示与质感体验，FLUX 等新一代。这只是一张粗略的地图，具体以你的显存和用途为准。

显存吃紧时的常见思路，按代价从低到高：降低出图分辨率或步数；换用参数更小的一代底模；先出小图再用放大模型补尺寸（见[AI 绘画由哪些部分组成](/concepts/components)）；再往后才是量化模型、分块 VAE、把部分计算挪回内存这类工具层手段，具体设置以所用工具的官方文档为准。

这条清单的末两档还藏着一层取舍值得单独说明。**量化（Quantization）** 把模型权重压成低精度数字，显存占用明显下降，代价是少量质量损失与偶发的兼容问题（词条见[术语表](/glossary#quantization)）；蒸馏加速版则减少步数、出图更快，代价是步数、CFG 这类参数的推荐值与原版明显不同，要按模型卡重新来。两者都是“用一点质量换低门槛”，适合先跑通再升级，不适合当作评价一个生态真实画质的依据。

### 版本号怎么读：家族、代际与变体

模型文件名像密码，拆开看有三层规律：

- **家族**：开头的大名号，如 SD、FLUX、Qwen-Image，代表一路技术谱系。家族之间没有直接可比性：画质、生态与硬件门槛要分别比较，数字大小跨家族没有意义。
- **代际**：家族里的数字，如 SD1.5、SD2.1、SDXL、SD3.5、FLUX.1、FLUX.2，代表架构换代。换代即换生态，这正是上一节分代的原因；SDXL 比 SD1.5 新，但拿 FLUX.2 与 SDXL 比“谁更新”是无效比较。
- **变体后缀**：同一代内的特化版本。常见的有 base（标准版）、inpaint（局部重绘特化）、turbo / lightning / hyper（蒸馏加速，步数大幅减少）、refiner（出图后精修用）。变体与主模型同生态、插件通常兼容，但推荐参数差别很大，用前看说明。

还有一层编号容易被混进来：社区 checkpoint 自带的 v1.0、v2.5 这类作者版本号（上一节说过）。分清层次再看文件名：官方数字是换架构、换生态，作者数字通常是同一模型的效果修订——判断“要不要换、能不能直接替换”的依据完全不同。

### 生态厚度怎么判断：选生态就是选社区

前文反复说“资源成熟度”，落到操作上，判断一个生态厚不厚可以看三件事：

- **教程密度**：搜“生态名 + 入门 / 工作流”，能搜到多少近一两年、与你的工具（如 [ComfyUI](/concepts/comfyui)）匹配的教程。教程少，意味着大量问题要自己啃。
- **附件数量**：在模型社区按 Base Model 筛选，看这个生态下的 LoRA 与 ControlNet 模型有多少、题材覆盖全不全。附件是生态的“存货”，用途见 [LoRA 入门](/lora/basics)与 [ControlNet 入门](/concepts/controlnet)。
- **答疑存量**：你将来遇到的报错，大概率别人也遇到过。搜一搜常见报错信息，有结果说明社区沉淀厚，一片寂静说明你可能要当第一个踩坑的人。

厚生态也有另一面：老生态的教程可能用过时的界面或早已淘汰的玩法，照着跑之前先看教程发布时间与所用工具版本。厚度是存量，工具与玩法是增量，两头都要看。

### 模型卡与许可证：用之前必须核对什么

模型卡（Model Card）是模型的说明书，下载前至少核对。各平台字段名称略有差异，但以下信息几乎总能在页面上找到：

- **Base Model**：它基于哪个生态，决定你的底模能不能带它。
- **推荐参数**：尺寸、步数、CFG、采样器、触发词（Trigger Words）。
- **训练数据声明**：作者用什么数据训练，涉及风格与版权边界。
- **已知问题与更新记录**：是否标注了缺陷、是否仍在维护。
- **许可证（License）**：最容易被忽略的一项。重点看三件事：能不能商用、能不能公开发布生成作品、能不能用它再训练并发布衍生模型（例如用某模型训练 LoRA 再分发）。许可证通常在模型页的 License 标签或说明区，官方模型在仓库的许可证文件里。

合规的底线：不用盗链或未授权分发的模型；公开发布作品前确认许可证允许；训练衍生模型前确认许可证允许二次创作。许可证没写清楚时，按“不允许”处理并向作者求证，而不是默认可以。

## 最小推演：陌生模型文件的“身份核查”

拿到一个陌生模型文件，先别急着加载，按顺序核对四处：

| 核对处 | 看什么 | 示例发现 | 由此得出 |
| --- | --- | --- | --- |
| 1. 文件名 | 命名是否含生态、版本、类型线索 | 名字带“XL”字样、体积 GB 级 | 疑似 SDXL 系 checkpoint |
| 2. 模型卡 | Base Model 字段与作者说明 | 标注 Base Model: SDXL | 确认是 SDXL 生态底模 |
| 3. 许可证 | 商用、发布、二次训练条款 | 仅允许非商用 | 只能个人学习使用 |
| 4. 配套文件 | 是否需要额外的 VAE、文本编码器或工作流 | 模型卡注明需单独下载 VAE | 记入待办，缺件不出图 |

推演步骤：

1. 文件名只做初步猜测，不能当结论——重命名太容易了。
2. 模型卡是权威依据：确认生态、配套文件（是否需要另装 VAE 或文本编码器）和触发词。
3. 许可证决定“能怎么用”：示例里允许下载学习、不允许商用，公开发布作品前就要另找方案。
4. 四处任一对不上（比如名字说 XL、模型卡说 1.5），停下来向发布者求证，不硬加载。
5. 把结论记进自己的模型清单（哪个生态、什么用途、什么限制），以后排查兼容性问题先查这份记录。

这个推演只说明“核查的顺序和依据”，不等于核查过就保证了质量与安全——来源不明的文件仍可能被篡改，尽量从官方或可信平台获取；核查记录也要随版本更新而更新。

## 对比表

下载目录里混着各种文件时，按“作用 + 体积量级 + 常见去处”区分：

| 类型 | 作用 | 典型大小量级 | 常见去处 |
| --- | --- | --- | --- |
| Checkpoint（底模） | 完整生成模型 | GB 级 | models/checkpoints（WebUI 习惯叫 Stable-diffusion） |
| LoRA | 底模上的小型附加模型 | 几十到几百 MB | models/loras |
| VAE | 潜空间与像素图转换 | 百 MB 级或更小 | models/vae |
| Embedding | 概念压缩成的提示词向量 | KB 到几 MB | models/embeddings |
| ControlNet 模型 | 按条件类型的控制模型 | GB 级 | models/controlnet |

目录名以所用工具的文档为准，这里给的是主流工具的常见习惯；认类型的关键不是文件后缀（常见都是 `.safetensors`），而是模型页对用途的说明。量级也只是心理预期：同类型文件随模型代际不同，大小可能相差数倍。

## 常见误区

- **“热门模型一定适合我”**：热门不等于匹配——生态兼容性、显存要求、你的用途与已有插件都影响选择。
- **“一个生态就是一个模型文件”**：新模型常由底模、文本编码器、VAE 等多个文件组成，缺件会导致报错或效果异常。
- **“公开发布作品不用看模型许可证”**：商用、公开发布、训练衍生 LoRA 都受许可证约束，发布前要核对。
- **“.safetensors 从哪下载都一样”**：来源不明的文件可能被篡改，`.ckpt` 还可能夹带可执行代码；认官方与可信平台。
- **“新模型一出就该立刻全面迁移”**：生态（LoRA、教程、工作流）需要时间积累，迁移应按需进行，成熟度常比新旧更重要。
- **“模型、LoRA、工作流的版本可以各管各的”**：它们经常按版本绑定，混搭出错时先查三者是否同代。
- **“变体只是名字花哨，随便下”**：inpaint、turbo、refiner 各有特化用途，用错场景效果明显走样——拿 turbo 版按普通模型的步数和 CFG 跑，结果反而更差；下载前看清变体类型与推荐参数。
- **“量化版、加速版和原版是同一个文件的几种叫法”**：量化与蒸馏都是再加工，各有质量与参数上的代价；想评价一个模型的真实水平，用未加工的原版测。

## 自测问题

### 1. checkpoint 和 LoRA 的体积量级差多少？为什么差这么多？

<details>
<summary>查看答案</summary>

checkpoint 是完整底模，通常 GB 级；LoRA 只存对底模权重的小幅修改（低秩的小矩阵），通常几十到几百 MB。因为 LoRA 冻结底模、只训练少量新增参数，所以文件小，也正因此必须挂在匹配的底模上使用；原理细节见 [LoRA 入门](/lora/basics)。

</details>

### 2. 下载一个陌生模型前，至少要核对哪四处信息？

<details>
<summary>查看答案</summary>

文件名（初步判断生态与类型）、模型卡（Base Model、推荐参数、触发词的权威依据）、许可证（能否商用、公开发布、二次训练）、配套文件（是否需要单独的 VAE 或文本编码器）。四处以模型卡和许可证为准，文件名只能当线索。

</details>

### 3. 想把用某模型生成的作品公开发布甚至商用，需要先看模型卡的什么字段？

<details>
<summary>查看答案</summary>

看许可证条款：是否允许公开发布生成作品、是否允许商用、是否有署名等附加要求。许可证没写清楚的，默认按不允许处理，向作者求证后再用，而不是默认可以。

</details>

### 4. 看到 `MysticXL_v3.5-inpainting.safetensors` 这样的文件名，不打开模型卡能读出哪些信息？哪些仍必须靠模型卡确认？

<details>
<summary>查看答案</summary>

能初步读出：家族疑似 SDXL 系（XL 字样）、作者自己的版本号 v3.5、变体为局部重绘特化（inpainting）、存储格式为 safetensors。仍必须靠模型卡确认：Base Model 标注是否真是 SDXL（文件名可以被随意重命名）、推荐参数（重绘类的步数与 CFG 常与普通版不同）、触发词与许可证。文件名只做线索，模型卡才是依据。

</details>

### 5. 为什么说“选生态也是在选社区”？判断一个生态厚不厚，可以看哪三件事？

<details>
<summary>查看答案</summary>

模型文件只是一次下载，而使用过程中需要的教程、LoRA 与 ControlNet 附件、报错答案，全靠社区长期积累；生态薄，处处要自己啃。三看：教程密度（能否搜到与所用工具匹配的新教程）、附件数量（按 Base Model 筛选 LoRA 与控制模型的覆盖面）、答疑存量（常见报错是否搜得到解答）。

</details>
