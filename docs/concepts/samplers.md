# 采样器与步数

> **一句话结论：** 采样器（Sampler）回答“每一步怎么走”，调度器（Scheduler）安排“每步减多少”，步数决定一共走多少步——它们决定的是去噪过程的节奏与手感，不是画面会画什么；采样器没有绝对好坏，从模型卡的推荐组合起步，胜过自己穷举。

## 前置知识

- 读过 [基本原理](/concepts/how-it-works)，知道生成是“从噪声出发、分多步去噪”；本页把那里一笔带过的“去噪节奏”展开成正文。
- 读过 [AI 绘画由哪些部分组成](/concepts/components) 会更顺：采样器、调度器、步数、CFG、seed 这几个旋钮在那里列过总表，本页只深挖其中一组。
- 不要求任何数学基础：本页不写公式，名字里的“SDE”“二阶”这类词只做直觉解释。
- 先接受一个边界：采样参数影响的是完成度与质感，用推荐值就能及格；它补不了底模能力的缺口。

## 学习目标

读完后，你应该能够：

- 把模型卡上一串“DPM++ 2M Karras、28 步、CFG 7”拆开，说出每一段在管什么。
- 区分采样器与调度器各自的分工，知道 Karras 是哪一侧的名字。
- 认出常见采样器名字的构成：算法名 + 变体标记 + 调度后缀。
- 用“固定 seed、步数加倍对照”的办法判断一张图的步数够不够。
- 说明 Turbo / Lightning / Hyper / LCM 这类加速模型为什么不能沿用普通模型的参数。
- 说清 CFG、seed 与采样器怎么互相牵制，养成一次只动一个旋钮的习惯。

## 核心概念

### 它解决什么问题：模型卡上那串参数到底在说什么

随便打开一个模型的说明页，你大概率会见到这样一行推荐参数：`DPM++ 2M Karras · Steps 28 · CFG 7`。新手常把它当成咒语照抄——先照抄是对的——但抄完不知道每段是什么，出了问题就无从下手。拆开看，这行字其实回答了三个问题：

- **DPM++ 2M Karras**：每一步怎么走。DPM++ 2M 是采样器的名字（算法），Karras 是调度器的名字（衰减曲线），两个名字拼在一起，管的是整个去噪过程的步态与节奏。
- **Steps 28**：一共走多少步。步数太少画面粗糙，够了之后再加通常只是更慢。
- **CFG 7**：每一步“听提示词”听得多用力。机制在 [基本原理](/concepts/how-it-works) 讲过：把“带提示词”与“不带提示词”两次预测的差距放大 CFG 倍。

三个问题对应三组旋钮，本页按这个顺序展开。先说清一件事：这串参数是模型作者验证过的起点，不是必须精确遵守的法律——顺着它起步，再一次只动一个旋钮，比一上来就穷举组合划算得多。

### 采样器与调度器：一个管步态，一个管节奏

[AI 绘画由哪些部分组成](/concepts/components)里给过一句话分工，这里画成图：

```text
从噪声到图片的一条路线（以 28 步为例）：

纯噪声 → [步 1] → [步 2] → …… → [步 28] → 成图
            ↑
            每一步内部：
            · 调度器给出这一步该减多少噪声（步幅）
            · 采样器按自己的算法走完这一步（步态）
            · CFG 决定这一步听提示词的力度
```

- **采样器（Sampler）**是具体走路的算法（词条见[术语表](/glossary#sampler)）：拿到当前这层噪声和模型的预测后，怎么算出下一步的图。不同算法步态不同——有的步幅大、收敛快，有的步子细、细节稳，有的会故意掺一点随机性。
- **调度器（Scheduler）**是安排节奏的规则：给定总步数，它把“从满噪声到零噪声”切成多少份、每步减多少——通常前期大幅去噪定结构、后期小步精修出细节（词条见[术语表](/glossary#scheduler)）。

两个名字经常拼在一起出现，因为它们成对工作：调度器定每步的减噪量，采样器按这个量走。同一采样器换调度器、或同一调度器换采样器，走出来的细节和稳定感都可能不同——[AI 绘画由哪些部分组成](/concepts/components)说“DPM++ 2M Karras 是采样器（及其调度）的名字”，指的就是这种搭配关系。

但要记住本页开头那句话：换它们改变的是“怎么走”，不是“会画什么”。画面画什么由底模和条件决定；采样参数没有绝对好坏，只有与模型的搭配是否合适——这也是为什么每张模型卡都替你写好了推荐组合。既然要先照抄，下一节就把这些名字教会你读。

### 常见名字怎么读：算法名 + 变体标记 + 调度后缀

采样器名字看着唬人，拆开就三层：算法名（Euler、DPM++、UniPC）+ 变体标记（a、SDE、2M 这类修饰）+ 调度后缀（Karras 等，属于调度器一侧）。算法名那一层，社区常这么概括：

| 名字 | 一句话特征 | 注意点 |
| --- | --- | --- |
| Euler | 最简单直观，快而稳 | 大多数场景的第一默认 |
| Euler a（ancestral，祖先采样） | 每步注入随机性，细节活 | 步数改变时画面会继续变化，复现性弱 |
| Heun | 二阶，更精确 | 每步算两次，更慢 |
| DPM++ 2M | 二阶多步，质量速度均衡 | 最常见的“通用推荐” |
| DPM++ SDE（随机微分方程） | 随机性带来细节质感 | 更慢，跨参数复现差 |
| UniPC | 统一预测-校正，少步表现好 | 步数紧张时值得一试 |

这张表是“社区常这么说”的经验概括，不是评测结论：同一名字在不同模型上的实际表现有差异，快慢与效果请以你自己的对照为准。两个变体标记值得多说一句：**a（ancestral，祖先采样）**表示每步额外注入一点随机噪声，“多走几步”不只是在原画面上精修，而是继续添细节——想要完全可复现的结果就别选它；**SDE** 把去噪过程当作带随机性的方程来解，质感与复现性的取舍类似，只是随机性的来源不同。

调度后缀那一层，一句话带过就够，不必记公式：

| 后缀 | 一句话特征 |
| --- | --- |
| normal | 默认的均匀衰减，无特殊标记时多半就是它 |
| simple | 更简单的衰减方式 |
| karras | 衰减曲线后期更细腻，收尾细节是它的口碑 |
| sgm_uniform | 均匀式衰减的另一变体，少步模型常用 |
| beta | 按另一类曲线分配每步减噪量 |

名字会读之后，选择策略反而简单：这些名字之间没有全局最优，模型卡推荐什么就用什么起步；想换，也在推荐组合的基础上一次换一处、固定 seed 对照着看。

### 步数：画质与时间的折中

[基本原理](/concepts/how-it-works)给过结论：步数太少画面粗糙，适中后趋于稳定，再多通常只是更慢。这里补上“适中”怎么找。关键概念是**稳定区**：从某一步数开始，再加步数带不来可见的画质改善，只是白白多等。不同模型的稳定区差得很远——普通模型常在二三十步一带，蒸馏加速模型把步数压到个位数到十来步（下一节单说）。

判断别凭感觉，做一次对照：固定 seed 与提示词、CFG 等其他参数，把步数加倍再跑一张。新图没有可见改善，说明当前步数已进入稳定区，不必再加；明显更干净，说明原来去噪不彻底。这套对照的本质是单变量实验：seed 固定了起点，其余参数固定了路径，剩下的差异才能归因给步数——下一节的最小推演把完整流程走一遍。

边界也在这里：步数解决的是“去噪彻不彻底”，治不了内容层面的病。人物结构崩坏、手画错，多半不是步数的锅——那要回头查底模、提示词和 CFG。步数真正常见的两个用途：出图太慢时先降它，画面粗糙时先怀疑它，代价都比换硬件小得多。

### 加速模型：步数压下来的代价是什么

有一类模型专门为“少步”而生：文件名或模型卡里带 **Turbo、Lightning、Hyper、LCM** 字样的，多是蒸馏加速版——用蒸馏（Distillation，词条见[术语表](/glossary#distillation)）的手段，让模型学会“少走几步就到位”，把步数压到个位数到十来步。

代价藏在参数习惯里，而且不小：

- **推荐步数完全不同**：普通模型二三十步的稳定区经验到这里全部作废，它可能四五步就到位。
- **推荐 CFG 完全不同**：不少加速版与新代模型推荐值低得多，甚至固定为 1（关闭引导放大）。拿普通模型的 CFG 7 去跑加速版，画面反而更差。

所以“旧模型的参数照搬到新模型”是新手最容易踩的坑之一：参数手感是跟着模型走的，不是跟着你的习惯走的。换了模型，第一件事是翻开新模型卡，把步数、CFG、采样器整套按新推荐重新填，再固定 seed 出基准图。加速版适合快速出图、确认构图、低显存救急；追求最终画质时，再用原版模型细跑——两种用途，不是取代关系。

顺带一提：新一代模型转向流匹配（Flow Matching，词条见[术语表](/glossary#flow-matching)）等训练目标后，“从噪声逐步还原”的直觉不变，但默认步数与参数习惯又是一套新的——再次说明，一切以模型卡为准。

### 参数联动：CFG、seed 与采样器怎么互相影响

三个旋钮不是各自独立的，收尾把它们串起来：

- **CFG 与采样器互相牵制**。CFG 决定每一步“听提示词的力度”（引导公式见[基本原理](/concepts/how-it-works)），采样器决定每一步怎么把这个力度走完——同一个 CFG 值换一个采样器，贴合提示词的观感可能不同；带随机性的采样器（Euler a、SDE 系）在高 CFG 下更容易放大过头的症状。
- **seed 是一切对照的前提**。想比较任何改动（换采样器、加步数、动 [CFG](/glossary#cfg)），都必须固定 [seed](/glossary#seed)：起点相同，差异才能归因到那个旋钮。反过来说，seed 只保住起点——你换了采样器或步数，去噪路径照样分岔，两张图本来就该不同。
- **步数与复现绑在一起**。带随机性的采样器还有个特点：改步数不只是“画得更细”，画面本身会变——想复现一张图，采样器、步数、seed 必须整套一起固定。

由此得到全页的操作纪律：**一次只动一个旋钮**。先用模型卡推荐的一整套参数固定 seed 出基准图，然后每次只改一处，把差异记下来。旋钮之间互相牵制，同时动两个，你就说不清效果是谁的功劳。

## 最小推演：为一张图找到合适的步数

任务：不查资料、不问人，自己为一个模型找到“够了”的步数。

1. 选定模型，把模型卡推荐的采样器、调度器、步数、CFG 一整套填进去，固定 seed 和一句简单的提示词，出第一张基准图。
2. 其他一格不动，把步数加倍（例如 28 改 56），再出一张。
3. 对照两张图的细节、线条与噪点：没有可见差别，说明当前步数已进入稳定区，收工；明显更干净，说明原来的步数去噪不彻底，在两个步数之间再取一档试一轮，逐步收窄。
4. （可选）换一个采样器，从头重复第 1 到 3 步。你大概率会发现不同采样器的稳定区位置也不同——这正是“参数组合跟着模型走”的直观体现。
5. 把结论记下来：这个模型、这套参数下，多少步够用。下次换模型，这套流程从头再来。

这个推演只说明参数的手感——找到你的模型在你的提示词下的稳定区，不等于找到了“最优组合”，也不等于结论能搬到别的模型上；画质的上限始终由底模决定，步数只是让它充分发挥。

## 对比表

普通模型与蒸馏加速版，是同一件事的两套参数习惯：

| 维度 | 传统模型（普通 28 步一带） | 蒸馏加速版（Turbo / Lightning / Hyper / LCM） |
| --- | --- | --- |
| 步数 | 二三十步一带，稳定区靠对照实验找 | 个位数到十来步，模型卡直接给推荐值 |
| CFG | 常从 5 到 8 起步 | 明显更低，甚至固定为 1（关闭放大） |
| 出图时间 | 随步数增多而变长 | 步数少，出图快 |
| 适用场景 | 追求画质上限、精修出图 | 快速出图、确认构图、低显存救急 |

表里没有采样器一栏，因为它在两侧的选法相同：没有全局最优，按模型卡推荐起步。这张表唯一的通用规则是：换了模型就重新读模型卡，参数习惯不跨模型搬运。

## 常见误区

- **“步数越多画质越好”**：超过稳定区之后收益极低，通常只是更慢；先用加倍对照找到“够了”的位置，再谈其他。
- **“换个采样器能治画面崩坏”**：崩坏的根源常在底模能力、提示词冲突或 CFG 过高；采样器只决定每步怎么走，治不了内容与结构层面的病。
- **“采样器决定画风”**：想换画风，换底模或挂 LoRA；采样器影响的是细节与稳定感的表现方式，不是画面的内容倾向。
- **“采样器有玄学排名，背下来就赢”**：同一名字在不同模型上表现有差异，跟着模型卡或教程的推荐组合走，胜过穷举试错。
- **“Karras 一定更好”**：它只是调度器的一种衰减曲线，“后期更细腻”是社区口碑，不是普适结论；选什么仍以模型卡为准。
- **“旧模型的参数照搬到新模型”**：参数手感跟着模型走，普通模型、加速版、新一代模型的推荐值各成一套；换模型先读新模型卡。

## 自测问题

### 1. 采样器和调度器分别管什么？它们怎么配合？

<details>
<summary>查看答案</summary>

采样器回答“每一步怎么走”：拿到当前噪声与模型预测后，用什么算法算出下一步的图。调度器回答“每步减多少”：把从满噪声到零噪声的过程按总步数切开，安排每步的去噪量，通常前期大幅去噪、后期精修细节。两者成对工作——调度器定节奏，采样器按节奏走——所以名字经常拼在一起出现，DPM++ 2M Karras 里的 Karras 就是调度器一侧的名字。

</details>

### 2. 怎么判断一个模型的步数够不够？

<details>
<summary>查看答案</summary>

固定 seed 与提示词、CFG 等其他参数，按模型卡推荐步数出一张图，再把步数加倍出第二张。第二张没有可见改善，说明已进入稳定区，不必再加；明显更干净，说明原来的步数去噪不彻底。普通模型常在二三十步一带，加速模型在个位数到十来步，但准确位置以你自己的对照实验为准。

</details>

### 3. Euler 和 Euler a 有什么区别？

<details>
<summary>查看答案</summary>

a 是 ancestral（祖先采样）的标记：Euler a 每一步额外注入一点随机性，细节更活，但步数改变时画面会继续变化——加步数不是单纯精修，而是继续添内容——复现性弱。普通 Euler 更直观稳定，可复现性更好。社区常把 Euler 当第一默认，把 Euler a 当“想要细节活力”时的选项；具体选哪个仍以模型卡与你的对照为准。

</details>

### 4. 为什么 Turbo 这类加速模型不能沿用普通模型的参数？

<details>
<summary>查看答案</summary>

加速模型经过蒸馏，学会了少走几步就到位：步数压到个位数到十来步，CFG 等参数的推荐值也与普通模型完全不同，不少加速版甚至固定 CFG 为 1。拿普通模型的 28 步、CFG 7 去跑，等于把另一套节奏硬套在它身上，结果反而更差。换任何模型（包括普通换普通）都应先读新模型卡，整套重新填参数，再固定 seed 出基准图。

</details>

### 5. 构图崩坏了，为什么换采样器治不了？该查什么？

<details>
<summary>查看答案</summary>

采样器只决定去噪每一步“怎么走”，改变不了“会画什么”；构图、结构这类内容层面的问题出在条件与能力上。排查顺序：先看底模有没有这个能力，再看提示词是否冲突、负向是否漏写，然后看 CFG 是否过高、插件权重是否过激，最后才轮到怀疑采样参数。参数只能让已有能力发挥得好一点，补不了能力的缺口。

</details>
