# ComfyUI 入门

> **一句话结论：** ComfyUI 是节点式（Node-based）的本地 AI 绘画界面：把生成流程拆成一个一个节点，连线决定数据怎么流，一张图从加载模型到保存的每一步都摊开在画布上。分工一句话：模型管“会画什么”，工作流（Workflow）管“怎么画”，ComfyUI 是把“怎么画”摊开在桌面上，让你看得见、也改得动的工具。

## 前置知识

- 读过 [AI 绘画由哪些部分组成](/concepts/components) 会最顺：ComfyUI 的节点就是把那里讲的部件一个个摆出来；再读过 [基本原理](/concepts/how-it-works)，连线的背后在做什么就不再神秘。
- 不要求任何编程经验：搭工作流全程是拖节点、连线、填参数、点运行，纯图形界面操作。
- 先接受一个边界：ComfyUI 只是搭流程的工具，模型能力仍是基础——工具不产生能力，只组织能力。

## 学习目标

读完后，你应该能够：

- 看懂一张文生图工作流的节点链，说出每个节点在干什么。
- 说清 ComfyUI、WebUI、在线生成平台三类工具各自的分工与适合人群。
- 照着教程搭出（或连出）你的第一个文生图工作流。
- 会放模型文件：checkpoint、LoRA、VAE、ControlNet 各归其位。
- 区分“换工作流”与“换模型”分别改变什么。
- 排查最常见的三类报错：缺模型文件、缺节点、显存不够。
- 知道去哪找官方文档、官方示例工作流和配套教程。

## 核心概念

### 它是什么：把生成流程拆成节点

[常用工具](/tools/common-tools)里给过定位：ComfyUI 是节点式本地界面，把生成流程拆成可自由连接的节点，适合理解模型数据流、精细控制和复用工作流。对照按钮式界面（如 Stable Diffusion WebUI），差别可以这么理解：按钮式界面把常用操作固定成一个个按钮和滑杆，你看不到操作之间怎么衔接；节点式界面把这些衔接摊开——每个环节一个节点，你亲手连出整条流程。

三个词先认熟：

- **节点（Node）**：一个部件的图形化封装，有输入口、输出口和参数区。比如加载模型的节点，参数区让你选文件，输出口把模型交给下一个节点。
- **连线**：数据的流向。从一个节点的输出口拖到另一个节点的输入口，数据就按这条线流动；连错口、漏连线，流程就跑不通。
- **画布**：所有节点和连线铺在一张可缩放的画布上，从左到右大致就是执行顺序。

对零基础读者，节点式还有个额外好处：流程被逼着摆到明面上，许多“玄学问题”在这里直接现形——没连 VAE Decode 就是不会出图，缺了负向那路编码就没处填负向提示词。按钮式界面里这些问题藏在按钮背后，你只能猜。

[工作流](/glossary#workflow)在这里的定义与 [AI 绘画由哪些部分组成](/concepts/components) 一致：把生成部件按顺序连接的执行流程，在 ComfyUI 里表现为节点图。同一个模型可以配多种工作流；工作流只是流程，模型能力仍是基础。这句话是全页的地基——下一节先看最基础的那张流程长什么样。

### 文生图主干的节点链：五个节点跑通第一张图

最基础的文生图工作流，主干只有一条链（节点名以所用版本为准，部分界面会译成中文）：

```text
Checkpoint Loader (Simple) → CLIP Text Encode（正向、负向各一个）→ KSampler → VAE Decode → Save Image
      （载入底模及配套文件）      （提示词 → 向量）                （分步去噪）  （latent → 图片） （保存结果）
```

- **Checkpoint Loader (Simple)**：一个节点同时载入底模（Checkpoint）与配套的 CLIP、VAE，不必分别加载。
- **CLIP Text Encode**：把提示词翻译成模型能理解的向量，正向、负向各接一个——正向写想要的内容，负向写想避免的内容。
- **KSampler**：去噪全过程发生在这里，四个旋钮见下一节。
- **VAE Decode**：把潜空间图像（latent）翻译成人眼可见的图片，缺它不出图。latent 是压缩过的图像工作区——去噪不直接在像素上做，而是在这张小得多的“草稿层”上进行，最后才由 VAE 翻译回来，这就是它要单独占一个节点的原因。
- **Save Image**：保存结果，各版本命名略有差异。

初次打开 ComfyUI 不必从空白画布搭起：官方默认就带这张主干工作流，模板菜单里也有现成的起步图。第一次的目标不是理解每个参数，而是认出这条链与[基本原理](/concepts/how-it-works)讲的“从噪声逐步去噪”一一对应——连线连的就是数据真正流动的顺序。

### KSampler：四个旋钮收在一个节点

概念里的采样器（Sampler）、调度器（Scheduler）、步数（Steps）、CFG 四个旋钮，在 ComfyUI 里全部收进 KSampler 一个节点的参数区——模型卡上写“用 DPM++ 2M Karras、28 步、CFG 7”，填的就是这个节点的那几项：

| 旋钮 | 管什么 | 口径 |
| --- | --- | --- |
| [采样器](/glossary#sampler) + 调度器 | 每一步怎么走 | 没有全局最优，跟模型卡或教程推荐的组合走；换采样器改变“怎么走”，不是“会画什么” |
| 步数 | 去噪迭代次数 | 太少画面粗糙不完整，够了之后再加通常只是更慢 |
| [CFG](/glossary#cfg) | 模型听提示词的程度 | 太低自由发挥、容易跑题；过高颜色过饱和、结构僵硬 |
| [seed](/glossary#seed) | 决定起点噪声 | 固定才能复现结果、做对照实验 |

还有一点要提醒：这些推荐值随模型代际变化，Turbo、蒸馏加速类模型的步数与 CFG 推荐值明显更小——换了模型就按新模型卡重新填，别沿用旧习惯（见[常见模型生态](/models/ecosystems)）；每个旋钮背后的逻辑，展开在 [采样器与步数](/concepts/samplers)。

新手不必穷举组合：先把模型卡或教程推荐的一整套参数填进去，固定 seed 出一张基准图，再一次只动一个旋钮。这套“单变量对照”的纪律在 [AI 绘画由哪些部分组成](/concepts/components) 里完整讲过，ComfyUI 只是给它换了一张操作台——旋钮还是那些旋钮。

### 挂附件：LoRA 与 ControlNet 插在哪

主干不变，附件各插各的位置：

- **LoRA**：LoRA Loader 节点接在底模与采样器之间，可以串联多个——每个节点载入一个 LoRA 文件、设一个权重，再把结果传给下一个。挂多了会互相干扰，一次只加一个并固定 seed 观察（见 [LoRA 入门](/lora/basics)）。
- **ControlNet**：一条支路，按“加载图像 → 预处理（Preprocessor）节点 → Apply ControlNet 类节点 → KSampler”的顺序接进主干：参考图先提取成条件图，再与提示词编码在采样前合流（原理与选型见 [ControlNet 入门](/concepts/controlnet)）。

看懂别人的工作流有个取巧办法：先找到主干五节点，再看附件插在哪一段。网上流传的复杂工作流，绝大多数都是这条主干加不同附件的组合，认出主干就不会迷路。

### 模型文件与工作流文件：东西放哪、流程存哪

用 ComfyUI 要管好两类文件。第一类是模型文件，按类型放进 models 目录下的对应文件夹（目录名以所用工具文档为准，这里给主流习惯）：

| 类型 | 常见去处 | 一句话 |
| --- | --- | --- |
| Checkpoint（底模） | models/checkpoints | 能力的来源，由加载节点载入 |
| LoRA | models/loras | 底模上的小型附加模型 |
| VAE | models/vae | 缺失或不匹配时颜色容易发灰 |
| ControlNet 模型 | models/controlnet | 按条件类型选用 |

放错位置的文件不会出现在节点的下拉列表里——加载节点里找不到文件，第一反应是查它放没放对地方。另外别靠文件后缀认类型：主流文件常见都是 `.safetensors`，认类型看模型页对用途的说明；各类型的量级与来源核查流程，[常见模型生态](/models/ecosystems)有完整说明。

第二类是工作流文件：在画布上调好的工作流连同参数保存成一个文件，下次载入只改提示词——跑通的流程沉淀为可复用起点（口径见 [工作流和模板区别](/workflows/workflow-vs-template)）。这是节点式工具的核心价值之一：你交给别人的不是一句“参数这样设”的说明，而是整张可运行的流程图。

### 自定义节点与显存：装插件、爆显存怎么办

主干五节点之外的功能，靠**自定义节点（Custom Nodes）**补充：社区写的扩展，通过管理器（ComfyUI Manager）安装，类比“装插件”。两条边界要知道：来源要挑，优先官方和社区验证过的；装多了排查困难——遇到报错先怀疑缺节点或版本不兼容，而不是怀疑自己连错了线。

显存方面记两条类别边界就够。一，新一代大模型常提供 FP8/量化（Quantization）版本：用更低精度的数字存储模型权重，换更小的显存占用，是低显存跑大模型的常用路子（词条见 [FP8/量化](/glossary#quantization)，代价是少量质量损失）。二，爆显存（提示内存不足或直接报错）时按代价从小到大处理：先降出图分辨率、降步数、减 LoRA，都不行再想换卡。显存边界记住了，下一节就把这些零件串成一次完整的动手流程。

## 最小推演：跑通第一张图

任务：装好 ComfyUI 后，出第一张图。

1. 打开 ComfyUI，载入默认工作流（或从模板菜单选一张文生图起步图），主干五节点已经连好。
2. 把底模文件放进 models/checkpoints，在 Checkpoint Loader (Simple) 的下拉列表里选中它。
3. 正向 CLIP Text Encode 写一句简单的提示词，负向写想避免的内容。
4. KSampler 按模型卡填推荐参数（例如 DPM++ 2M Karras、28 步、CFG 7），seed 先固定。
5. 点队列运行：KSampler 走完步数，VAE Decode 出图，Save Image 里看到结果。
6. 只改提示词再跑两张，换一个 seed 再跑一张——亲眼看到“改哪一格、变哪一处”。

这个推演只说明“工作流就是生成流水线的可视化、改参数就是拧流程上的一格”，不等于你已经理解每个旋钮的原理——那要回到 [基本原理](/concepts/how-it-works) 与 [AI 绘画由哪些部分组成](/concepts/components)；也不等于装好就一定能跑——报错时先看提示缺什么，这正是下一节对比三类工具前要记住的预期。

## 对比表

三类绘画入口不是谁取代谁，而是投入程度与控制力度的三档：

| 维度 | 在线生成平台 | Stable Diffusion WebUI | ComfyUI |
| --- | --- | --- | --- |
| 使用方式 | 网页填词出图 | 按钮式本地界面 | 节点式本地界面 |
| 上手门槛 | 最低，无需本地硬件 | 中：安装配置加一定硬件 | 中偏高：要理解节点与数据流 |
| 可控性 | 平台给什么用什么 | 参数面板固定，插件扩展 | 流程自由搭、精细控制 |
| 流程复用 | 基本没有 | 部分参数可存预设 | 工作流连参数存成文件，载入即用 |
| 界面生态 | 各平台自行迭代 | 近年更新放缓，新项目多转向 ComfyUI | 当前新项目的主要落点 |
| 适合谁 | 快速体验、确认兴趣 | 跟随传统教程、用成熟插件生态 | 想理解数据流、精细控制、复用流程的人 |

一句话分工：在线工具管“先画出来”，WebUI 管“本地常用操作按钮化”，ComfyUI 管“把流程摊开、存下来、反复用”。零基础可以从在线平台确认兴趣，再决定要不要装本地工具；装了本地工具，也不必一步追求复杂工作流——上一节那条五节点主干就够跑很久。

## 常见误区

- **“ComfyUI 出图效果比别的工具好”**：能力来自模型，工具只组织流程；同一底模、同一套参数，换界面不会变好。模型能力仍是基础。
- **“导入工作流就能跑”**：工作流依赖模型文件、节点和路径，缺一样都跑不起来；报错信息通常已指出缺什么，先看报错再动手。
- **“节点越多越专业”**：文生图主干就五个节点，其余按需增加；一上来照抄几十个节点的复杂工作流，出错时连哪一段在做什么都说不清。
- **“换采样器能换一种画风”**：换采样器改变“每一步怎么走”，不是“会画什么”；想换画风与能力，换底模或挂 LoRA。
- **“自定义节点装得越多越强大”**：装多了启动变慢、报错难排查，来源不明的还有安全风险；够用就停，来源要挑。
- **“爆显存就只能换显卡”**：先降分辨率、降步数、减 LoRA，或改用 FP8/量化版本；多数情况轮不到动硬件。

## 自测问题

### 1. 模型卡写“用 DPM++ 2M Karras、28 步、CFG 7”，这些参数填在 ComfyUI 的哪个节点？

<details>
<summary>查看答案</summary>

填在 KSampler 节点。采样器与调度器、步数、CFG 这四个旋钮在 ComfyUI 里全部收进 KSampler 一个节点的参数区；seed 也在这个节点里。推荐组合没有优劣推理可走时，直接照模型卡或教程填，固定 seed 出基准图后再逐个试改。

</details>

### 2. 从网上下载的工作流载入后直接报错，最常见的三个原因是什么？第一步做什么？

<details>
<summary>查看答案</summary>

缺模型文件（底模、LoRA、VAE 没下载或没放进 models 对应文件夹）、缺自定义节点或版本不兼容、文件路径对不上。第一步是看报错信息——它通常已经指出缺什么：缺模型就去补文件并放对位置，缺节点就用管理器安装，而不是整条重搭或重装软件。

</details>

### 3. LoRA Loader 接在哪两个节点之间？ControlNet 支路怎么接进主干？

<details>
<summary>查看答案</summary>

LoRA Loader 接在 Checkpoint Loader (Simple) 与 KSampler 之间，可以串联多个，每个各设一个权重。ControlNet 走支路：加载图像 → 预处理节点提取条件图 → Apply ControlNet 类节点 → 汇入 KSampler，条件信号与提示词编码在采样前合流，权重与介入阶段两个旋钮就填在 Apply ControlNet 类节点上。识别复杂工作流时，先找主干五节点，再看这两类附件插在哪。

</details>

### 4. “换采样器”和“换底模”分别改变什么？

<details>
<summary>查看答案</summary>

底模是能力的来源，决定“会画什么”，换它等于换地基；采样器只决定去噪每一步“怎么走”，影响细节与稳定感的表现方式，没有全局最优，跟模型卡或教程推荐的组合走。前者动内容与上限，后者只动过程——所以出图不满意时，先想清楚问题出在哪一层，再决定动哪个。

</details>

### 5. 生成时提示内存不足（爆显存），按什么顺序处理最省力？

<details>
<summary>查看答案</summary>

按代价从小到大：先降出图分辨率，再降步数，然后减挂载的 LoRA 数量或降低权重；还不行就改用 FP8/量化版本的模型文件。这些都试过仍不够，才考虑换更大显存的硬件——多数新手遇到的情况，前几步就能解决。

</details>
