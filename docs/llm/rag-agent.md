# RAG 与 Agent

> **一句话结论：** RAG 让模型先检索资料再回答，解决知识时效、私域知识和引用溯源问题；Agent 让模型围绕目标规划步骤并调用工具，从“回答问题”升级为“完成任务”。

- 已阅读 [推理与解码](/llm/inference-decoding)，知道模型逐 Token 生成、推理时参数固定。

## 核心概念

### RAG：先查资料，再回答

**RAG（Retrieval-Augmented Generation，检索增强生成）**在模型回答之前，先从外部资料中找出相关片段，再让模型基于资料作答。典型流程：

```text
离线准备：文档 -> 切分成片段 -> 每个片段算 Embedding -> 建立语义索引
在线回答：用户提问 -> 问题也算 Embedding -> 检索最相似的若干片段（Top-K）
         -> 片段连同问题拼进 Prompt -> 模型基于资料生成回答
```

（这里的 K 指检索返回的条数，与解码采样里的 Top-k 参数无关。）

为什么需要 RAG：

- **知识时效**：模型参数在训练时固定，训练截止之后的新信息它不知道；检索可以随时接入新资料。
- **私域知识**：内部文档、公司制度这类资料模型从没见过，不能指望它凭空知道。
- **引用溯源**：回答可以标注“来自哪篇文档”，方便人工核查，这是降低幻觉风险最直接的机制之一。
- **成本更低**：更新知识只需更新资料库，不需要重新训练模型。

RAG 的核心不是“把所有文档塞给模型”，而是把最相关、可信、足够短的材料放进上下文。

适合：企业知识库问答、产品文档助手、法规制度查询、需要引用来源的总结、资料经常更新的场景。不适合：没有可靠原始资料的问题、需要复杂事务操作但没有工具接口的问题、文档本身质量很差且互相矛盾的场景。

RAG 的常见失败点：切分太碎导致答案缺上下文、检索召回不准、塞入太多无关片段、没有来源标记无法复查、文档版本混乱新旧混杂。

### RAG 与微调怎么选

- 需要固定的格式、语气、分类标准：考虑微调。
- 需要回答经常变化的文档、制度、产品资料：优先 RAG。
- 需要严格引用来源：优先 RAG。
- 想降低幻觉：RAG 加评估，比盲目微调更直接。
- 两者可以组合：RAG 提供事实，微调稳定行为和风格。

### Agent：规划、记忆、工具调用

**Agent** 不只是回答问题，而是围绕目标执行一组动作。它通常由三部分组成：

- **规划（Planning）**：把目标拆解成步骤，决定下一步做什么。
- **记忆（Memory）**：短期记忆是当前对话的上下文；长期记忆通常靠外部存储（例如用向量检索实现的资料库）来补充。
- **工具调用（Tool Use / Function Calling）**：模型输出结构化参数，由程序调用实际函数去查实时数据、做计算、读写数据库或调用业务系统。

Function Calling 把模型不擅长的部分交给工具：查实时数据、运行精确计算、操作数据库、验证文件和代码。Agent 的关键不是“像人一样自主”，而是让模型在受控边界内使用工具完成任务。设计原则：

- 工具权限最小化。
- 重要动作要有确认或审计。
- 工具输入输出要结构化。
- 不让模型凭空假设工具结果。
- 对失败路径和重试次数做限制。

### Agent 与普通对话的区别，以及多步任务的失败模式

普通对话是一问一答，单轮生成；Agent 是“思考 → 行动 → 观察结果 → 再思考”的多步循环，直到完成目标或触发停止条件。与固定流程的 Workflow 相比，Agent 的路径由模型根据中间结果动态决定。三者的分工：RAG 重点是“查资料后回答”，Agent 重点是“规划和执行动作”，Workflow 重点是“固定流程自动化”——RAG 也常常只是 Agent 的一件工具。

多步不等于更可靠，每一步的可靠性会被连乘：假设每步正确率 95%，十步全对的概率只有约 60%（0.95 的 10 次方；工作流编排中错误连乘的展开例子见[工作流和模板区别](/workflows/workflow-vs-template)）。常见失败模式：

- 某一步检索或工具调用出错，后续步骤全被带偏。
- 目标漂移：做着做着偏离了最初的任务。
- 死循环：反复重试同一个失败动作。
- 错误累积：每步的小误差，最后放大成完全错误的结果。

所以 Agent 需要检查点、结果校验和人工确认，而不是默认“步数越多越聪明”。

## 最小推演：手工做一次 RAG

假设资料库只有三篇短文档：

| 编号 | 标题 | 内容 |
| --- | --- | --- |
| 1 | 年假制度 | 员工每年有 5 天带薪年假，入职满两年增加 2 天，需提前 3 个工作日在系统申请。 |
| 2 | 报销流程 | 差旅报销需在返回后 10 个工作日内提交，并附发票原件。 |
| 3 | 考勤规定 | 工作日 9:00 至 18:00，迟到 30 分钟以上记警告一次。 |

用户问题：“年假要提前多久申请？”

第 1 步，检索。用最粗糙的“词面重合”模拟相似度——数问题里的词在各文档中出现了几个：

| 文档 | 与问题重合的词 | 得分 | 结果 |
| --- | --- | ---: | --- |
| 1 年假制度 | 年假、提前、申请 | 3 | Top-1，拼入 Prompt |
| 2 报销流程 | 无 | 0 | 落选 |
| 3 考勤规定 | 无 | 0 | 落选 |

第 2 步，拼 Prompt。把 Top-1 片段放进模板：

```text
请仅根据以下资料回答问题，并在答案末尾注明来源编号。

[资料1]（年假制度）：员工每年有 5 天带薪年假，入职满两年增加 2 天，
需提前 3 个工作日在系统申请。

问题：年假要提前多久申请？
```

第 3 步，生成。模型基于资料输出：“年假需提前 3 个工作日在系统申请（来源：资料1）。”

这个推演用词面重合代替了真实检索，只说明“检索 → 拼 Prompt → 带引用生成”的数据流，不等于真实系统——真实 RAG 用向量相似度而非字面重合，能把“休假”和“年假”这类字面不同但语义相关的词匹配上，但也可能引入噪声，所以检索质量本身需要单独评估。

## 对比表

四种方案解决不同的问题：

| 方案 | 知识来源 | 擅长 | 主要局限 | 典型场景 |
| --- | --- | --- | --- | --- |
| 直接问模型 | 训练时学进参数的知识 | 通用问答、写作、解释 | 知识截止、可能幻觉、无引用 | 日常对话、文案草稿 |
| RAG | 外部知识库实时检索 | 时效与私域知识、引用溯源 | 依赖检索质量和文档质量 | 企业知识库问答 |
| 微调 | 把行为风格学进参数 | 稳定格式、语气、任务模式 | 不擅长更新知识、可能遗忘 | 固定话术与格式 |
| Agent | 模型知识 + 检索 + 工具 | 多步任务、操作外部系统 | 步骤多、错误累积、需权限控制 | 自动化办公、代码助手 |

选择时先问“缺的是知识、行为还是执行”：缺知识用 RAG，行为不对用微调，需要执行用 Agent。

## 常见误区

- **“把所有文档塞进上下文就是 RAG”**：RAG 的核心恰恰是筛选——只检索最相关、可信、足够短的片段；全部塞入既稀释关键资料，又白白增加成本。
- **“有了 RAG 就不会幻觉”**：检索不到、文档质量差或模型不忠实于资料时仍会出错；RAG 降低风险，不消除风险。
- **“微调能让模型学会新知识”**：微调主要改变行为与表达；知识更新更适合 RAG。
- **“Agent 越自主越好”**：自主度越高越难控制；关键是让模型在受控边界内完成任务，权限要最小化。
- **“RAG 和 Agent 是竞争关系”**：RAG 常常就是 Agent 调用的一件工具，两者是组合关系。
- **“多步 Agent 每步都对，所以整体更强”**：每步的错误会累积，步数越多整体可靠性越低，需要检查点与人工确认。

## 自测问题

### 1. 按顺序说出 RAG 的流程，并解释为什么“引用溯源”靠 RAG 容易实现？

<details>
<summary>查看答案</summary>

流程：切分文档 → 向量化并建立索引 → 用户提问时检索相似片段 → 把片段拼进 Prompt → 模型基于资料生成。因为回答所依据的片段是检索进来的明确文档，Prompt 中可以带上来源编号，输出时标注出处，答案与原文的对应关系可以直接人工核查。

</details>

### 2. 公司要做“经常更新的内部制度”问答，选微调还是 RAG？为什么？

<details>
<summary>查看答案</summary>

选 RAG。制度经常更新，写进参数很快过期，重新训练成本高；RAG 只需更新资料库，还能标注来源便于核实。前提是文档本身质量可靠，切分和检索经过评估。

</details>

### 3. Agent 的三个组成部分是什么？它和普通对话的本质区别是什么？

<details>
<summary>查看答案</summary>

规划（拆解目标、决定下一步）、记忆（短期上下文与长期外部存储）、工具调用（输出结构化参数，由程序执行实际函数）。本质区别：普通对话是单轮回答，Agent 是“思考-行动-观察”的多步循环，会调用工具改变外部世界，直到完成目标。

</details>
