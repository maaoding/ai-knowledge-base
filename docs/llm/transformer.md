# Transformer 直觉

> **一句话结论：** Transformer 是现代大语言模型的核心架构，它用注意力机制让每个 Token 动态关注上下文里相关的部分，并支持并行计算，因此取代了 RNN 等早期序列模型。

## 前置知识

- 已阅读 [Tokenization 与 Embedding](/llm/tokenization-embedding)，知道文本会变成 Token 向量，也了解位置信息要单独处理。
- 不要求矩阵运算或微积分；推演只用加法、乘法、加权平均和 softmax 的换算结果，不出现任何推导。
- 先接受一个边界：本页目标是建立直觉，不推导完整数学细节；真实的注意力在几十维以上的向量上做乘法，这里全部简化。

## 学习目标

读完后，你应该能够：

- 用“检索匹配”的类比解释注意力机制（Query、Key、Value）在做什么。
- 说明多头注意力和多层堆叠各自增加什么能力。
- 说明注意力、前馈网络、残差连接和层归一化在一层里各自负责什么。
- 解释为什么注意力机制还需要位置信息。
- 区分 Transformer 与 RNN 在处理方式上的差别。
- 判断关于 Transformer 的常见错误说法。

## 核心概念

### 为什么需要注意力：词义取决于上下文

语言不是逐词孤立理解的：

- “苹果”可能是水果，也可能是公司。
- “它”指代谁，要看前文。
- 代码里同一个变量名的含义，取决于定义和调用位置。

如果每个 Token 只有一个固定不变的向量，同一个词在不同语境里就无法区分。**[注意力机制（Attention）](/glossary#attention)**让每个 Token 根据上下文动态调整自己的表示，相当于把“词的含义由上下文决定”变成了可计算的过程。

### 注意力怎么工作：查询、键、值

可以把每个 Token 想象成同时扮演三个角色：

- **查询（Query）**：我在找什么信息。
- **键（Key）**：我能提供什么标签。
- **值（Value）**：我实际携带的内容。

类比一次图书馆检索：Query 是你的搜索词，Key 是每本书的书脊标签，Value 是书的正文。搜索词和标签越匹配，这本书的正文在你的结果里占比越高。

**自注意力（Self-Attention）**把这个过程用在同一段输入内部，每个 Token 都会：

```text
1. 用自己的 Query 和所有 Token 的 Key 比较，得到相关性分数
2. 把分数换算成权重（对一个查询，所有权重加起来等于 1）
3. 按权重加权平均所有 Token 的 Value
4. 得到融合了上下文的新表示
```

最后一步的加权平均就是“信息流动”：权重越大，那个 Token 的信息进入当前 Token 新表示的比例越高。

这套相关性不是人工写死的规则，而是模型在训练中学出来的：真实模型里，Query、Key、Value 都是由可学习的参数矩阵从 Token 向量变换出来的，同一个 Token 在不同层、不同头里会得到不同的三件套。

### 多头与多层：换个角度看，一层层加深

**多头注意力（Multi-Head Attention）**是把上面的过程并行做多次，每组独立的 Query、Key、Value 从不同角度观察上下文：

- 一个头可能关注语法关系。
- 一个头可能关注指代关系。
- 一个头可能关注代码结构。
- 一个头可能关注格式边界。

**多层堆叠（Layer）**则是把每一层注意力的输出再送进下一层，逐层精炼。底层可能更多处理相邻词、词性这类局部模式，高层更接近语义和任务相关的抽象表示。每过一层，“每个 Token 的表示”都被上下文更新一次。

Transformer 家族还有不同的形态：BERT 类模型是双向编码的 encoder-only（只做理解、不负责生成），擅长理解类任务；GPT 类对话模型是解码器（decoder-only），生成时使用带**因果掩码（Causal Mask）**的自注意力——每个 Token 只能看到它前面的 Token，这正是“根据前文预测下一个词”能够逐字进行的原因；完整的编码器-解码器结构则常见于翻译这类序列到序列任务。当前主流大语言模型基本都是 decoder-only 形态。此外，截至 2026 年，旗舰与主流开源模型（如 DeepSeek-V3/R1、Qwen3 的 MoE 版本、Llama 4 等）普遍采用稀疏混合专家（MoE）结构：把前馈层拆成多个“专家”，每个 Token 只激活其中一小部分，用更大的总参数量换更低的推理成本。

### 注意力之外：前馈网络、残差连接与层归一化

注意力不是 Transformer 层的全部。一个完整的 Transformer 层大致按这条流水线运转：

```text
输入 -> 注意力（Token 之间交流）-> 残差连接与层归一化（保底）
     -> 前馈网络（每个 Token 自己消化）-> 残差连接与层归一化 -> 交给下一层
```

不同模型在细节上有差别——比如层归一化放在子层之前还是之后就有两种做法——上图取便于理解的画法；关键是“交流、消化、保底”三类组件的分工。

- **前馈网络（Feed-Forward Network，FFN）**：注意力负责“Token 之间交换信息”，前馈网络则对每个位置的表示**独立地**做一次小型的两层变换——像开会先交流，散会后每个人回到座位独自消化。前文提到的稀疏混合专家（MoE），改造的正是这一层。
- **残差连接（Residual Connection）**：把这一层的输入原封不动加到输出上。这样即使某一层学得不好，原始信息也不会丢失，梯度还能沿这条“高速公路”顺畅流回浅层——这是几十上百层的网络仍然训得动的关键条件之一（梯度是什么，见 [神经网络直觉](/ai/neural-networks)）。
- **层归一化（Layer Normalization）**：把每层输出的数值分布拉回稳定范围，防止数值逐层放大或缩小导致训练不稳。

三者的分工一句话记住：注意力管交流，前馈管消化，残差和归一化管“别把信息弄丢、别让数值失控”。本页最后的手算推演只演到流水线的第一站；真实模型要把“交流—消化”循环重复几十层，才把初始 Token 向量加工成上下文表示。

### 位置信息与 Transformer 为什么取代 RNN

注意力本身对顺序不敏感：把输入 Token 的顺序打乱，不加位置信息的注意力计算结果基本不变。但语言强依赖顺序——“猫追狗”和“狗追猫”意思相反，代码、表格和列表也不能乱序。所以模型必须额外注入**[位置编码（Positional Encoding）](/glossary#positional-encoding)**或类似机制，告诉模型每个 Token 在序列中的位置（具体机制见 [Tokenization 与 Embedding](/llm/tokenization-embedding)）。

在 Transformer（2017 年提出）之前，主流序列模型是 **RNN（循环神经网络，Recurrent Neural Network）**：逐个 Token 顺序处理，把前面的计算结果传给后面。它有两个短板：

- 必须逐个计算，后一步依赖前一步，难以并行，训练慢。
- 远距离信息要一步步传递，容易被稀释，长程依赖很难学到。

Transformer 用注意力让任意两个 Token 一步直连，距离不再衰减；整个序列可以并行计算，训练效率大幅提升。代价是注意力要求每对 Token 两两比较，计算量随序列长度增长得更快——这也是上下文窗口有限、长上下文成本高的一个原因。新的序列架构仍在演进，但当前主流大语言模型几乎都建立在 Transformer 之上。

## 最小推演：手算三个词的注意力

句子：`小猫 追 球`。假设已经算出三个 Token 之间的相关性（真实模型中这一步由训练出的参数计算），且每行加起来等于 1：

| 查询 \ 键 | 小猫 | 追 | 球 |
| --- | ---: | ---: | ---: |
| 小猫 | 0.1 | 0.4 | 0.5 |
| 追 | 0.5 | 0.1 | 0.4 |
| 球 | 0.4 | 0.3 | 0.3 |

以“追”这一行为例：它作为查询时，对“小猫”权重 0.5、对自己 0.1、对“球”权重 0.4。再给三个 Token 随意设定玩具 Value 向量：小猫 `[1, 0]`、追 `[0, 1]`、球 `[0, 1]`，则“追”的新表示为：

```text
0.5 × [1, 0] + 0.1 × [0, 1] + 0.4 × [0, 1] = [0.5, 0.5]
```

新表示里有一半信息来自“小猫”——动词“追”由此知道了自己的主语，也顺带吸收了宾语“球”的信息。用同样方法算“小猫”那一行：

```text
0.1 × [1, 0] + 0.4 × [0, 1] + 0.5 × [0, 1] = [0.1, 0.9]
```

“小猫”的注意力重心同样落在了别的词上。注意力就是这样让信息在 Token 之间按权重流动，每个 Token 的新表示都由全句共同塑造。

最后把“球”这一行也补上，三个 Token 的新表示就齐了。“球”的权重是 0.4、0.3、0.3：

```text
0.4 × [1, 0] + 0.3 × [0, 1] + 0.3 × [0, 1] = [0.4, 0.6]
```

“球”从“小猫”那里吸收了四成信息——宾语由此知道了“追我的是谁”。

**权重从哪来？**推演开头假设“相关性已经算好”，这里补上缺失的一环。真实模型里，相关性来自 Query 和 Key 的匹配程度：把两个向量逐维相乘再求和（这个运算叫**点积（Dot Product）**），方向大致相同时得到大正数，接近垂直时接近零，方向相反时是负数。举个两维的小例子，Query 是 `[1, 1]`，三个 Key 分别是 `[2, 0]`、`[0, 1]`、`[1, -2]`，匹配分数依次是：

```text
[1,1]·[2,0]  = 1×2 + 1×0  = 2
[1,1]·[0,1]  = 1×0 + 1×1  = 1
[1,1]·[1,-2] = 1×1 + 1×(-2) = -1
```

原始分数还不是权重：注意力要求每个查询对所有 Token 的权重加起来等于 1，这一步由 softmax 完成。softmax 粗略说做两件事：把任意分数换算成加和为 1 的百分比，并放大分数之间的差距。对上面这组分数 `2、1、-1`，softmax 给出的权重大约是 `70.5%`、`25.9%`、`3.5%`——分数最大和最小只差 3，权重却差了约 20 倍。差距被放大，正是注意力能够“聚焦”的来源。

回到主表：那一行权重 `0.5、0.1、0.4` 同样可以由一组分数换算而来——`1.6、0、1.4` 经 softmax 约等于 `0.49、0.10、0.41`，四舍五入正是表中的数字。也就是说，表格里每一行权重背后，都藏着一次“点积打分、softmax 归一”的换算。

这个推演补上了“分数怎么来、权重怎么定、信息怎么加权”的完整链条，但仍不等于真实注意力——真实模型的相关性由训练学出的 Query、Key、Value 在几十到几千维的向量上计算得出，同一层还有多个头并行做这件事，并且整个过程逐层重复。

## 对比表

两种架构处理序列的方式截然不同：

| 维度 | RNN | Transformer |
| --- | --- | --- |
| 处理方式 | 逐个 Token 顺序处理 | 整个序列并行计算 |
| 远距离信息 | 逐步传递，容易衰减 | 任意两个 Token 一步直连 |
| 训练效率 | 难以并行，训练慢 | 并行度高，训练快 |
| 顺序信息 | 按顺序读入，天然知道先后 | 注意力不认顺序，需要位置编码 |
| 长序列计算量 | 随长度近似线性增长 | 两两比较，随长度增长更快 |

Transformer 并非全方位更优：长上下文的计算成本正是它的短板，但凭借并行和长程依赖两项优势，它成为当前大语言模型的主流选择。

## 常见误区

- **“Attention 是在模仿人类注意力”**：它只是一个加权汇总的数学机制，名字是类比，与人类的注意过程无关。
- **“相关性和权重是人写死的”**：Query、Key、Value 和相关性分数都来自训练学到的参数。
- **“注意力天然知道词序”**：不加位置信息时，注意力对顺序基本不敏感；顺序要靠位置编码等机制注入。
- **“层数和头数越多一定越好”**：收益会递减，成本会上升，效果还取决于数据质量与训练方法。
- **“上下文越长效果一定越好”**：注意力要在全部 Token 上分配权重，塞进来的无关内容会分走权重、稀释真正相关的信息，长上下文还需要检索、排序和压缩配合。
- **“Transformer 能真正理解世界”**：它学到的是可泛化的模式和表示，不自动保证事实正确。
- **“注意力层就是 Transformer 的全部”**：完整的 Transformer 层还包括前馈网络、残差连接和层归一化；注意力负责 Token 之间交流，前馈网络负责逐 Token 加工，缺一不可。
- **“残差连接只是可有可无的实现细节”**：它是深层网络训得动的关键之一；去掉这条“高速公路”，几十层的模型很难稳定训练。

## 自测问题

### 1. 用图书馆检索类比，说明 Query、Key、Value 分别对应什么？

<details>
<summary>查看答案</summary>

Query 对应你输入的搜索词，Key 对应每本书的书脊标签，Value 对应书的内容。搜索词与标签越匹配，这本书的正文在结果中占比越高；在注意力里，相关性越高，该 Token 的信息就越多地融入当前 Token 的新表示。

</details>

### 2. 为什么 Transformer 的训练比 RNN 快？

<details>
<summary>查看答案</summary>

RNN 必须按顺序逐个 Token 计算，后一步依赖前一步的结果，难以并行；Transformer 的注意力对所有 Token 同时做两两比较，整个序列可以并行计算，训练效率大幅提高。

</details>

### 3. 注意力机制为什么还需要位置编码？

<details>
<summary>查看答案</summary>

注意力计算本身对 Token 的先后顺序不敏感，打乱顺序结果基本不变；而语言、代码、表格都强依赖顺序，所以必须用位置编码或类似机制把位置信息注入模型。

</details>

### 4. 一层 Transformer 里，注意力、前馈网络、残差连接各自负责什么？

<details>
<summary>查看答案</summary>

注意力负责 Token 之间的信息交流，按相关性加权汇总上下文；前馈网络对每个位置的表示独立做变换，相当于各 Token 自己消化交流结果；残差连接把本层输入原样加到输出上，给信息和梯度留了一条原样通行的旁路，让几十上百层的网络训得动。层归一化则把每层的数值拉回稳定范围。

</details>

### 5. 推演里，Query `[1,1]` 对三个 Key `[2,0]`、`[0,1]`、`[1,-2]` 的匹配分数是 2、1、-1，经 softmax 后权重大约是 70.5%、25.9%、3.5%。这说明 softmax 在注意力里起了什么作用？

<details>
<summary>查看答案</summary>

两件事：把任意分数换算成加和为 1 的权重，并放大分数差距——原始分数最大和最小只差 3，权重却差了约 20 倍。差距被放大，注意力才能“聚焦”到最相关的 Token 上，而不是对上下文一视同仁地平均。

</details>
