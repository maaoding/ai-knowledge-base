# 大模型入门

> **一句话结论：** LLM（Large Language Model，大语言模型）是用海量文本和代码训练出来的模型，核心任务是根据上下文逐个预测下一个 Token；它表达流畅、用途广泛，但不会自动保证事实正确。

## 前置知识

- 已阅读 [AI 基础概念](/ai/basics)，知道模型是训练得到的产物、训练与推理的区别——这里的“推理”指模型运行（Inference），与“多步思考”意义上的推理不同，见[推理与解码](/llm/inference-decoding)；读过 [机器学习入门](/ai/machine-learning) 会更顺，但不强制。
- 不要求编程或数学基础，本页的推演只用计数和加法；对 [Tokenization 与 Embedding](/llm/tokenization-embedding) 里的 Token 概念有印象即可，没读过也不影响。
- 先接受一个边界：本页只搭建整体框架，训练阶段的细节在 [训练、微调与对齐](/llm/training-alignment) 展开，逐 Token 生成的采样机制在 [推理与解码](/llm/inference-decoding) 展开。

## 学习目标

读完后，你应该能够：

- 说明 LLM 的核心任务为什么是“根据上下文预测下一个 Token”。
- 区分预训练、微调（SFT）和对齐三个阶段各自解决什么问题。
- 解释逐 Token 生成的工作方式，以及对话能力是怎么来的。
- 判断哪些任务适合直接交给 LLM，哪些需要检索或工具补充。
- 解释上下文窗口与“记忆”的关系，以及 Token 数量如何影响成本与延迟。
- 识别幻觉等典型局限，并说明它为什么会发生。

## 核心概念

### 什么是大语言模型

**大语言模型（Large Language Model，LLM）**是用海量文本和代码训练出来的深度学习模型。它可以处理和生成自然语言，也常能处理代码、表格等结构化文本，部分模型还能理解图片、音频或视频。

这种能同时处理文字与图片、音频等多种输入输出的能力叫**多模态（Multimodal）**。本站为了讲清原理，把文字理解和图像生成分成两条线讲；真实产品正在走向融合——同一个助手既能对话，又能看图、生图。

它擅长：

- 总结、改写、翻译。
- 问答和解释。
- 代码生成和调试。
- 信息抽取和结构化。
- 规划步骤、辅助决策。

它不擅长：

- 自动保证事实正确。
- 长期稳定记住所有历史对话。
- 在缺少上下文时知道你的私有信息。
- 对所有数学、逻辑和最新事实做到零错误。

围绕 LLM 的常见应用形态：Chat（对话问答）、Copilot（在软件或代码环境里辅助操作）、RAG（先检索资料再回答）、Agent（规划步骤并调用工具）、Workflow（把模型调用放进固定业务流程）。RAG 和 Agent 在 [RAG 与 Agent](/llm/rag-agent) 单独展开；Workflow 与模板的区别见 [工作流和模板区别](/workflows/workflow-vs-template)。

### 三个训练阶段：预训练 → 微调 → 对齐

今天的对话模型通常经历三个阶段：

```text
预训练：海量文本 + “预测下一个 Token”任务 -> 通用基座模型
微调（SFT）：成对的“指令-回答”示例 -> 会遵循指令的模型
对齐（RLHF 等）：人类偏好反馈 -> 行为更符合人类期望的模型
```

**预训练（Pre-training）**阶段，模型在海量网页、书籍、代码上反复做一件事：看到前文，预测下一个 Token。目标足够简单，却逼着模型学到语言模式、知识关联、代码结构、推理模板和大量世界常识。

但预训练模型只会“续写”：你问它问题，它可能接着写出一串新问题。**微调**——通常指**指令微调（SFT，Supervised Fine-Tuning）**——用大量“指令-回答”示例教它按指令回答；**对齐（Alignment）**再通过人类偏好反馈，调整它“愿意回答什么”和“怎么回答”，让输出更有帮助、更安全。

一句话概括：预训练给能力，微调教用法，对齐定边界。

### 模型如何生成文本：一次只预测一个 Token

LLM 的基本训练目标就是**预测下一个 Token（Next-Token Prediction）**。生成一段话时，它每次只预测一个 Token，接回输入，再预测下一个：

```text
输入：今天天气
第 1 步：预测下一个 Token，得到“真”，接回输入
第 2 步：根据“今天天气真”预测，得到“不”，接回输入
第 3 步：继续预测，直到生成结束符或达到长度上限
```

为什么如此朴素的目标能产生对话、写作和写代码的能力？因为要把海量文本的下一个 Token 预测得足够准，模型必须学会语法、事实关联和推理模式：看到“天空是”就该接“蓝色”，看到一段报错就该知道接下来补什么代码。至于每一步“选哪个 Token”（总是选最高分，还是按概率抽样），属于解码与采样问题，见 [推理与解码](/llm/inference-decoding)。

### 规模与能力：更大意味着什么，局限在哪

一般来说，参数更多、数据更多、算力更多的模型，能在更多任务上表现更好；但“更大”不保证在每个具体任务上都更强，效果还取决于训练数据质量、训练方法和任务匹配度，而且更大的模型通常更慢、更贵。

同时，LLM 有几类结构性局限：

- **[幻觉（Hallucination）](/glossary#hallucination)**：生成了看似合理但不真实的内容。常出现在问题缺少上下文、资料已过期、要求给出引用却没有提供资料的时候；根源是模型在按概率生成“像样的续写”，而不是在查证事实。
- **知识截止（Knowledge Cutoff）**：模型的世界停在训练数据截止的那一天，之后的新事件、新产品默认答不上来。
- **上下文窗口（Context Window）**：一次能处理的 Token 数量有限，超长对话和超长文档放不下。
- **不会主动获取外部信息**：除非系统接入检索或工具，模型无法自己查数据库或上网核实。

降低幻觉的实用做法：提供原始资料、要求模型区分事实与推断、对最新信息做检索（RAG）、对关键输出人工复核。

核实也有讲究：涉及事实、数字、引用、法规的输出必须核对，核对要回到原始来源（论文原文、官方网站、官方文档），而不是把同一个问题再问一次模型；重要结论可以换另一个模型交叉验证。自己没把握时，明确说明这是待核实的内容，不要把流畅的输出当成已确认的事实转述出去。

### 什么时候交给 LLM，什么时候换工具

LLM 的主场是理解和生成语言：把一段意思讲清楚、换个说法、按指定格式整理、结合上下文补全。一旦任务的核心变成“事实必须准”或“计算必须对”，就要考虑换工具或加校验：

- **要出处、要最新的信息**：模型的知识停在训练截止，回答也不自带可靠来源。问“今天的汇率”“某个软件的最新版本”，先用搜索引擎或官方文档拿到材料，再让模型帮你阅读和整理。
- **精确计算与对账**：让 LLM “心算”多位数乘法，本质是按语言规律猜答案。更可靠的做法是让它写一小段代码或调用计算工具去执行，模型负责理解题意和检查思路。
- **需要逐字一致的部分**：合同编号、日期、固定格式的表格，让程序、模板或表格工具保证不变，LLM 只处理其中语言化的部分——它每次生成的措辞本来就可能不同。

一个实用标准：**语言转换交给 LLM，事实与计算外包出去**。把它当成“会读写、会总结的助理”，而不是“什么都知道的权威”，出错率会明显下降。需要新知识时接入检索，需要精确执行时接入工具，这两种扩展方式见 [RAG 与 Agent](/llm/rag-agent)。

### 上下文窗口与“记忆”：模型记得你吗

上下文窗口（词条见[术语表](/glossary#context-window)）是模型单次推理能看到的全部 Token 范围：系统指令、历史消息、你粘贴的资料和正在生成的回答都算在内。可以把窗口理解成模型的**工作记忆**——窗口里的内容，这一轮它都“看得见”；窗口外的内容，等于不存在。

由此能澄清一个常见误解——“模型记得我”。普通对话模型**跨会话默认不留任何记忆**：关掉对话再开一个新会话，模型看到的是空窗口，上次聊过什么它完全不知道。它“记得上文”，只是因为上文一直躺在当前会话的窗口里。

那产品里的“记忆”功能是怎么回事？那是模型之外的额外机制：产品把你的偏好或历史要点存进外部存储，等你发起新对话时，再把相关摘要作为资料注入上下文。模型本身没有变，“记住”发生在窗口之外。知道这一点有两个实际好处：涉及隐私的内容，别指望“删掉对话就彻底删除”，要看产品的数据政策；想让模型延续某个重要约定，就在新会话里主动重述，而不是假设它“应该记得”。

### Token 数量与成本、延迟的实务影响

LLM 服务通常按 Token 计费，输入和输出分开计价，输出一般比输入贵。落到日常使用，有三条直观影响：

- **粘贴不是免费的**：发给模型的每一段文字都是输入 Token，整本粘贴长文档会直接推高费用；要求“写一篇长文”的输出成本也比“问一句话”高。
- **上下文越长，响应越慢**：模型每生成一个 Token 都要结合窗口里已有的全部内容计算，输入越长，每一步的计算量越大，延迟越明显。
- **放不下就是放不下**：超出窗口的内容不会被自动“压缩理解”，可能被截断或直接导致请求失败。

使用原则是让上下文**够用且干净**：与任务相关的资料放进去，无关的历史和样板文字清出去；换了新任务就开新会话，不要把旧话题的长历史一路带着走。Token 如何切分、中英文数量为什么对不上，见 [Tokenization 与 Embedding](/llm/tokenization-embedding)；生成阶段为什么长上下文开销大，见 [推理与解码](/llm/inference-decoding)。

## 最小推演：用数数预测下一个字

假设语料只有 5 句话：

```text
我爱吃饭
我爱吃饭
我爱学习
我爱运动
猫爱睡觉
```

第 1 步，看前缀“我”。它在语料里出现 4 次，下一个字全部是“爱”，所以概率是 100%。

第 2 步，看前缀“我爱”。它出现 4 次，统计下一个字：

| 候选字 | 出现次数 | 概率（次数 ÷ 4） |
| --- | ---: | ---: |
| 吃 | 2 | 50% |
| 学 | 1 | 25% |
| 运 | 1 | 25% |

“睡”从未出现在“我爱”后面，概率为 0。第 3 步，逐字生成：每次按这张概率表选一个字接到句尾，再查新前缀的概率，循环往复——这就是“逐 Token 生成”最原始的形态。

这种“数前缀、数后继”的思路接近早期的统计语言模型（n-gram）。它只记得语料里出现过的组合，遇到没背过的前缀就束手无策。

这个推演只说明 LLM 的核心任务是“根据上下文预测下一个 Token 的概率分布”，不等于真实模型就是这样数出来的——真实模型把概率规律记在上亿个参数里，通过训练泛化到从未见过的组合，而不是对语料的字面计数。

## 对比表

三个训练阶段经常被混为一谈，下表从输入、目标、数据量级和产出四个维度区分：

| 阶段 | 输入数据 | 训练目标 | 数据量级 | 产出 |
| --- | --- | --- | --- | --- |
| 预训练 | 海量网页、书籍、代码等原始文本 | 预测下一个 Token | 海量，远超另外两个阶段 | 通用基座模型 |
| 微调（SFT） | 高质量的“指令-回答”示例 | 给定指令，生成合适回答 | 中等，常见为数千到百万级示例 | 会遵循指令的模型 |
| 对齐（RLHF 等） | 人类对多个回答的偏好比较 | 输出更有帮助、更安全 | 通常少于 SFT 数据 | 行为符合人类期望的模型 |

三个阶段不总是全部执行：有的模型只发布预训练版本供社区继续训练，有的轻量模型经过简单微调就能满足需求。

## 常见误区

- **“LLM 像人一样理解和思考”**：它学到的是文本中的统计规律和可泛化模式，没有人类式理解；换一种问法就可能让它出错。
- **“模型回答时在查资料库”**：普通对话不查任何资料，输出全部来自参数中学到的规律；需要新知识要靠 RAG 或工具。
- **“对话能力是预训练直接给的”**：只会续写的预训练模型不会好好回答问题；能聊天通常经过了指令微调和对齐。
- **“输出流畅说明内容正确”**：流畅度和正确性是两回事，幻觉恰恰常常非常流畅自信。
- **“模型越大，任何任务都更强”**：规模提升是总体趋势，具体任务还取决于数据质量与匹配度，并伴随更高的延迟和成本。
- **“Prompt 就是一句命令”**：好的 Prompt 通常包含任务、上下文、输出格式、约束等要素，进阶再加上角色与示例（详见 [Prompt 入门](/prompting/basics)），而不是简短的指令。
- **“模型记得上次聊过的内容”**：跨会话默认没有记忆，新会话的上下文窗口是空的；产品能“记住”，靠的是额外的存储和注入机制，不是模型自带记忆。
- **“上下文窗口越大，模型就越聪明”**：窗口大小只决定单次能装下多少文本，不改变参数里学到的能力；放不进窗口的内容，模型依然看不到。

## 自测问题

### 1. “预测下一个 Token”听起来这么简单，为什么能训练出会写代码、会对话的模型？

<details>
<summary>查看答案</summary>

因为要把海量文本的下一个 Token 预测得足够准，模型必须学会语法、事实关联、代码结构和推理模式，这些能力被压缩进参数；再经过微调和对齐，才转化为按指令行事、符合人类偏好的能力。目标简单，不等于学到的东西简单。

</details>

### 2. 你问了一件最近发生的事，模型答错了或自称不知道，为什么？

<details>
<summary>查看答案</summary>

推理阶段参数已经固定，模型只能使用训练截止前学到的内容，除非系统接入了联网检索或工具。如果它“一本正经”地回答了，还要警惕幻觉，而不是当作可靠答案。

</details>

### 3. 预训练、微调、对齐各主要解决什么问题？

<details>
<summary>查看答案</summary>

预训练用海量文本建立语言能力和知识基础；指令微调用“指令-回答”示例教模型按指令完成任务；对齐用人类偏好反馈调整模型“愿意回答什么、怎么回答”，让输出更有帮助、更安全。

</details>

### 4. 关掉对话再开一个新会话，模型就“不记得”之前聊过的内容了，为什么？产品里的“记忆”功能又是什么？

<details>
<summary>查看答案</summary>

模型的可用信息只有当前请求放进上下文窗口的内容；新会话的窗口是空的，旧会话的内容不会被自动带过来。产品的“记忆”功能是把你的偏好或历史要点存到外部存储，再在新对话中把相关摘要注入上下文——这是模型之外的额外机制，不是模型自带记忆。

</details>

### 5. 要总结一份 80 页的 PDF，直接整本粘贴是最优做法吗？从成本和效果两方面说明。

<details>
<summary>查看答案</summary>

不一定。整本粘贴意味着大量输入 Token，费用更高、响应更慢，无关章节还会稀释真正相关的内容，甚至超出窗口被截断。更稳妥的做法是先定位与任务相关的章节再粘贴，或者分段处理；无论哪种方式，结论都要抽查核对，防止幻觉。

</details>
